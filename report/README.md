# 设计报告与协作记录

报告应包含背景与创新点、设计原理/功能框图、软硬件划分、优化前后实测对比、复现说明、技能提炼及真实的大模型协作记录。当前架构见 [architecture](../docs/architecture.md)，运行见 [usage](../docs/usage.md)，数据出处见 [validation](../docs/validation.md)。

每个性能数字须指向 `metrics/evidence/` 或 `fpga/report/`，写明版本、输入与验证层次。当前相机直接连接板端，历史主机视频转运是另一条实验路线。不得混用旧路线结论；合成/stub、显示缓存和文件校验都不能当人体准确性或物理冷启动证明。

`llm_log/` 中现有记录与模板保留原文。每次协作须由人类亲手记录提示词、回答、自我纠错、采用修改与真实验证，AI 不得代写；详见 [AI 使用规则](../docs/ai_usage.md) 第五节。现有记录不代表后续协作记录已经补齐。

本机生成的竞赛 Word/PDF、打包清单与 RAR 位于忽略的 `deliverables/`，不作为公开仓库中的已验收结论。提交前按 [已知限制](../docs/limitations.md) 补全实卡验收、参考比对与人工协作记录。
