# report/ —— 设计报告素材 与 大模型协作记录

> ⚠️ **红线提醒（《05》第五节 + 第六节红灯清单）**：
> `llm_log/` 里的记录**必须你们亲手写**（真实提示词、真实回答、真实的纠错轨迹）。
> 让 AI 代写"大模型协作记录"本身，是《05》明确列出的红灯项。
> 本文件只提供**模板与归档规则**，不提供任何代写的内容。

## 目录

| 位置 | 内容 |
|---|---|
| `report/`（本层） | 设计报告素材、图表源数据、PPT 大纲、答辩口径 |
| `report/llm_log/` | 大模型协作记录，**赛制必交项**（《05》铁律 3） |

## llm_log 命名与归档规则

- 文件名：`YYYY-MM-DD_主题.md`（如 `2026-09-10_hls_roi_statistic_寄存器回填.md`）；
- 一条记录 = 一次真实的协作（一次提问 + 回答 + 你们怎么验证的）；
- 每周由一人汇总，检查是否有"AI 给了数字但仓库里没有对应真实日志"的情况（红灯项 1）。

模板见 `report/llm_log/_模板.md`（逐字抄自《05》第五节）。

## 报告写作时的三条真实性地雷

1. **数字必须有据**：报告里每一个性能/指标数字，都要能指向
   `metrics/evidence/` 或 `fpga/report/` 里的真实产物。
   注意 A 线摘要里的 `"landmark_source"`：为 `stub` 时 EAR/MAR 是**占位几何量**，
   不能作为算法结果引用（见 `backend/README.md`）。
2. **医疗措辞红线**（《00》第 1.3 节 + 《05》铁律 5）：
   ❌ 医疗诊断 / 疾病识别 / 健康评分 / 血氧 / 血压 / 医疗级精度
   ✅ 疲劳风险提示 / 状态趋势监测 / 非接触测量原型 / 受控条件下的心率呼吸趋势估计
3. **区分"仿真结论"与"上板结论"**：M3 之前所有 FPGA 数字都是 C 仿真/C 综合结果，
   报告中必须写明来源（`fpga/report/` 的报告文件名自带版本与日期）。
