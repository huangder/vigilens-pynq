## 3. 实质问题 ①：姿态判定污染（BUG-006 / BUG-007，P1，A 线，**待处理**）

| 指标 | 本机实测（656 帧） |
|---|---|
| `status = adjust_posture` | **644 / 656 = 98.2%**（`fatigue_risk` 7、`normal` 4、`unreliable` 1） |
| `\|yaw\| > 30°` 的帧 | **521 / 656 = 79.4%** |
| 相邻帧 `\|Δyaw\|` 最大 | **359.0°** |
| `yaw` / `pitch` / `roll` 范围 | −178.2~178.1 / −62.8~66.6 / **−180.0~180.0** |
| 逐帧 reason | `头部 yaw = 174.7° 超出 ±30°`、`-178.5°` … 在 ±175° 附近来回 |

**根因（本机 2026-09-27 重新确认，用卡里那个"不需要相机、不需要人脸"的数值复现脚本）**：

```
投影后各点 y: [540.0, 739.4, 439.7, 439.7, 628.9, 628.9]   ← 眼睛在鼻子上方、下巴在下方（正立正面）
-> 这套代码解出的姿态 (yaw, pitch, roll) = (0.0, 0.0, -180.0)
```

⇒ **是姿态解算代码的基准错误**（3D 模型点 Y 朝上 vs OpenCV 相机 Y 朝下 ⇒ 正立脸对应 `Rx(180)`），
**与视频、相机、光照都无关**。`decision.py` 的姿态分支先于疲劳分支触发，所以整段测量被压成"请调整姿势"。

> ⚠️ 这意味着 **A4 现在拿到的 `status` 全是噪声**：不能用它证明"系统判对了"，也不能用它证明"系统判错了疲劳"。

## 4. 实质问题 ②：眨眼检出被**未标定阈值**支配（DAT-001）

同一轮 656 帧的 EAR 分布与阈值扫描（`min_close_frames = 3`，连续帧数够才算一次闭眼）：

```
人脸可见 >=0.7 的帧 = 629 / 656 (96%)；EAR 中位 0.350、p5 0.248、最小 0.170

 阈值   低于它的帧数   连续段数   合格段数(=眨眼次数)
 0.15        0            0            0
 0.18        1            1            0
 0.20        7            6            0
 0.21        8            6            1      ← config.yaml 现值（ear_close_threshold）
 0.22       16            9            3
 0.24       31           13            3
 0.26       56           11            5
 0.28       76           12            8
 0.30       94           10            8
```

**读法**：
- 现值 **0.21 → 眨眼 1 次 / 2.75 per min**（22 s 内只算到 1 次）；
- 阈值只挪 **0.01**（0.22）→ **3 次**；挪到 0.28 → **8 次**（≈22/min，回到正常范围）；
- 而 `ear_close_threshold` 在 `config.yaml` 里被明确标为 **⚠️ 占位值**，`AGENTS.md` §9 与 `DAT-001` 都列着"**未标定**"。

⇒ **绝不能说"受试者眨眼少/不疲劳"**：这个 2.75/min 是阈值切出来的，不是人的状态。
这也是 `docs/14` §3 判据"最短可检出闭眼 = 3/fps"之外的另一条同类风险：**阈值未标定会让指标系统性偏低**。

**要标定必须先有 P4 素材**：`DAT-001` 仍缺 `still/blink/yawn/turn` 各 **mp4 + csv**（4+4）；
`data/annotations/` 现在只有 `.gitkeep`。**标注是人工 ground truth，AI 不得代写**（`AGENTS.md` 铁律 1）。
