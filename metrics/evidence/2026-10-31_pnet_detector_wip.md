# 2026-10-31 板端检测器尝试（PNet/ncnn）——未完成

目标：把轻量检测搬上板。本轮尝试了 PFLD-DEMO 自带的 MTCNN（det1/det2/det3，ncnn）
的 **PNet 阶段**，结果**不可用**，如实记录。

## 已完成的部分

- 从 `PFLD-DEMO.zip` 取出 det1/det2/det3 的 `.param/.bin`（ncnn 格式）；
- 确认板端可用的 ncnn 静态库（host 与 ARM）与头文件路径；
- 写了 `board/autonomy/pnet_probe.cpp`：读原始 BGR 帧 → 图像金字塔 → PNet →
  box 解码 → NMS，host 与 ARM 都能编译链接；
- 用 `blink.mp4` 第 100 帧做测试（MediaPipe 在同一帧的正检框为
  `222,145,235×235, score=0.903`）。

## 未解决的问题

| 检查 | 结果 |
|---|---|
| 整帧 640×480，阈值 0.6 | 145 个框，最大框在图像边缘（约 15 px），**没有脸** |
| 整帧，阈值 0.3 | 647 个框，**没有 width>40 的候选** |
| 人脸紧裁 235×235 缩到 48×48 | 仅 3 个小框（<8 px） |
| 通道顺序 BGR/RGB | 两种都试过，结果相同 |

结论：PNet 输出被正确读出（prob1/conv4-2 shape 正常），但**框解码/预处理未对齐**，
导致连"紧裁的人脸"都检不出。原因尚未定位，不能把该探针当检测器使用。

## 对项目的影响

- 板端检测仍缺位；当前可演示的是**混合链路**（板相机+PL，PC 检测/68 点，
  板端 PnP/指标/契约），已在 `2026-10-31_live_hybrid_demo.md` 记录。
- 继续做检测至少还需要：核对 det1 的输入约定（MTCNN 常见 12×12、(x-127.5)/128、
  RGB/BGR 顺序）、逐层对拍 ncnn 输出与已知实现、再补 RNet/ONet 与 NMS 阈值。

- 探针未接入 `camera_pl`，也未上板运行（host 结果已不可用，先不浪费板端时间）。
