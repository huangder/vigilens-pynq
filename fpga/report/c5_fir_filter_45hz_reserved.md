> **一句话**：45 fps 采样率的 FIR 系数**能生成、能算对**，但它解决的不是"测得更细"，

## 2. 背景与目标

- 需求来源：探讨把时间序列采样率从契约冻结的 **30 fps** 提升到 **45 fps**，为 rPPG 心率/呼吸
  提取"更细"的采样做准备。
- 本报告范围：**只做系数设计 + 算术验证 + 性能量化 + 文档**，**不改契约、不改 `fir_filter.cpp` 的默认系数**。
- 关键事实：`fir_filter.cpp` 的运算结构（对称折叠 MAC、`>>15`、饱和）**与系数数值无关**，
  45 fps 与 30 fps 的差别**只有 `fir_coeffs_q15.h` 里 63 个 Q15 系数**。

## 3. 系数设计（真实运行）

### 3.1 方法与口径

与 30 Hz 冻结设计**同一口径**（`design_fir_coeffs.py`）：Hamming 窗理想带通、**d=0.0**（设计边缘
= −6 dB 点 = 0.70/3.50 Hz）、通带峰值增益归一到 1.0、int16 Q15 四舍五入远离零。

选定 d=0.0 的理由与 30 Hz 基线一致（见 `c5_fir_filter_v1.md` §3.2）：**呼吸/基线漂移（0.1~0.5 Hz）
是 rPPG 最大干扰源**，宁可牺牲 0.7 Hz 附近通带完整度，也要保住呼吸带抑制。

### 3.2 d 扫描（真实运行，`design_fir_coeffs.py --fs 45 --scan`）

| 设计边缘外扩 d | −3dB 低/高 (Hz) | −6dB 低/高 (Hz) | 0.35 Hz | 0.5 Hz | 4.5 Hz | 1~3 Hz 起伏 |
|---|---|---|---|---|---|---|
| **0.00（本设计选定）** | 0.998 / 3.206 | 0.710 / 3.495 | **−11.5 dB** | **−9.0 dB** | −34.3 dB | 2.99 dB |
| 0.10 | 0.900 / 3.303 | 0.604 / 3.595 | −9.3 dB | −7.3 dB | −29.4 dB | 2.28 dB |
| 0.20 | 0.798 / 3.403 | 0.476 / 3.697 | −7.3 dB | −5.8 dB | −25.2 dB | 1.69 dB |
| 0.30 | 0.680 / 3.504 | 0.276 / 3.799 | −5.5 dB | −4.4 dB | −21.5 dB | 1.21 dB |

> 注：`place_3db` 自动搜索在 45 Hz 会选 **d=0.30**（让 −3dB 落回 0.68/3.50），但代价是
> **DC 抑制只剩 −6.97 dB、0.5 Hz 只剩 −4.4 dB**——呼吸带几乎压不住。故本预留设计**不采用** d=0.30，
> 沿用 d=0.0（与 30 Hz 基线同口径、同取舍）。

### 3.3 冻结系数（`fir_coeffs_q15_45hz.h`，真实生成）

`FIR_NUM_TAPS=63`、`FIR_FS_HZ=45`、`FIR_F1_HZ=0.70`、`FIR_F2_HZ=3.50`、`FIR_COEFF_SHIFT=15`。

峰值系数 **4062**、`Σh=5710`（DC −15.18 dB）、`Σ|h|=47582`、
累加器上界 `|acc| ≤ 32768·Σ|h| = 1,559,166,976 < 2³¹−1` → **不溢出 ✅**。

## 4. 30 vs 45 Hz 性能对比（核心发现，全部真实运行）

同口径（N=63、d=0.0、−6dB 设计边缘 0.70/3.50）下，仅采样率不同：

| 指标 | 30 Hz（冻结基线） | 45 Hz（本预留） | 方向 |
|---|---|---|---|
| Hamming 过渡带 `Δf≈3.3/(2πN)·fs` | **0.250 Hz** | **0.375 Hz** | ⬆ 变宽（根因） |
| −3 dB 点 | 0.895 / 3.305 Hz | **0.998 / 3.206 Hz** | ⬇ 通带向内收缩 |
| −6 dB 点 | 0.704 / 3.496 Hz | 0.710 / 3.495 Hz | ≈ 持平（口径一致） |
| DC 抑制（Σh） | **−31.25 dB**（Σh=897） | **−15.18 dB**（Σh=5710） | ⬇ 恶化 16 dB |
| 0.35 Hz 抑制 | **−16.2 dB** | **−11.5 dB** | ⬇ 恶化 4.7 dB |
| 0.5 Hz 抑制 | **−11.0 dB** | **−9.0 dB** | ⬇ 恶化 2.0 dB |
| 1.0~3.0 Hz 平台起伏 | 1.90 dB | 2.99 dB | ⬇ 变差 1.1 dB |
| 高阻带最差 | −16.0 dB @3.85 | −11.9 dB @3.85 | ⬇ 恶化 |
| 群延迟（时间） | 1033.3 ms | **688.9 ms** | ✅ 更短（31 样本 / 更快采样） |

**逐点增益对比（抽样点 Hz → dB）**：

| 频率 (Hz) | 0.1 | 0.3 | 0.5 | 0.7 | 1.0 | 1.5 | 2.0 | 2.5 | 3.0 | 3.5 | 4.0 | 5.0 | 8.0 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 30 Hz | −28.4 | −18.3 | −11.0 | −6.1 | −1.9 | −0.1 | −0.0 | −0.0 | −0.6 | −6.1 | −22.9 | −68.0 | −80.2 |
| 45 Hz | −14.8 | −12.3 | −9.0 | −6.1 | −3.0 | −0.5 | −0.0 | −0.2 | −1.7 | −6.1 | −15.4 | −50.9 | −86.3 |

### 4.1 怎么解读（诚实结论）

1. **呼吸/DC 分离能力下降**：45 Hz 的 0.1~0.5 Hz 抑制从 −11~−28 dB 退化到 −9~−15 dB。
   根因是过渡带变宽，滤波器低频裙边变缓，直流与呼吸漂移更容易漏进心率带。
2. **群延迟时间更短**：31 个样本在 45 Hz 下只有 688.9 ms（30 Hz 是 1033.3 ms），这是 45 fps **唯一**的
   时间域收益——但在"趋势监测"这种分钟级场景里，几百毫秒的差别没有实质意义。
3. **高阻带范围更宽**：45 Hz 的 Nyquist 是 22.5 Hz（30 Hz 只有 15 Hz），理论上能滤到更高频的伪影；
   但心率带本身只要 0.7~3.5 Hz，这个"更宽的 Nyquist"对心率提取没有直接收益。

### 5.2 主机端算术模型（`host_model_fir.cpp` 加 `-DFIR_45HZ` 编译）

```
== host_model_fir: N=63, shift=15, Σh=5710, Σ|h|=47582 ==
   |acc| 上界 = 32768 * Σ|h| = 1559166976  (int32 上限 2147483647) -> 不溢出 ✅
-- 结果 --
   int32+对称折叠 vs Python 黄金参考：逐样本相等 ✅（不一致 0 个样本）
   对称折叠 vs 朴素长整型累加   ：逐位相同 ✅（不一致 0 个样本）
   段：15 passed, 0 failed；饱和样本合计 0
   饱和路径覆盖：有饱和=0 无饱和=1（两种情况都必须出现）
   警告：饱和/非饱和覆盖不完整
```

**如实判读**：

- **算术正确性两项全部通过**：黄金参考 0 不一致、对称折叠 vs 朴素 0 不一致、15/15 段通过。
- 唯一 `FAIL` 来自**饱和路径覆盖检查**：45 Hz 峰值系数 4062 < 30 Hz 的 6101、`Σ|h|` 47582 < 55073，
  所以**同样的满幅测试向量在 45 Hz 下不再削波**（30 Hz 下 `square_1hz_full` 饱和 33 样本）。
- 饱和分支代码（`if shifted > 32767 … clamp … sat_cnt++`）**只依赖数值、不依赖系数**，
  已在 30 Hz 基线验证过（`c5_fir_filter_v1.md` §5.1 用例 8 + §7 cosim PASS）。
  45 Hz 不触发饱和是**更安全的方向**，不是新增风险。

## 6. FPGA 资源 / 时序（实测，2026-09-13）

`fir_filter.cpp` 的综合结构（63 抽头完全分区延迟线、对称折叠 MAC、II=1 流水线）**与系数数值无关**：
HLS 会把 `static const` 系数表**常量折叠**进乘法器，无论系数是 30 Hz 还是 45 Hz 的值，
乘法器数量、延迟线寄存器、流水线结构都相同。因此：

| 项 | 30 Hz 实测（c5 报告） | 45 Hz **实测（2026-09-13）** |
|---|---|---|
| Final II | 1 | **1** |
| Estimated Fmax | 146.97 MHz | **154.38 MHz** |
| LUT / FF / BRAM / DSP | 4077 / 6172 / 0 / 25 | **4043 / 6174 / 0 / 26** |

> ✅ 以上为**实测**（2026-09-13，完整权限终端重跑）。系数数值确实让资源/时序**略有变化**
> （DSP 25→26、LUT 4077→4043、Fmax 146.97→154.38 MHz），并非"完全相同"——
> `static const` 系数被常量折叠进乘法器，不同系数图案的 DSP 打包/布线略有差异。
> 但仍 II=1、Fmax 远超 100 MHz 目标、BRAM 保持 0。

## 7. 结论与建议

1. **已采纳为默认、待会签**：45 fps 系数表已并入 `fir_coeffs_q15.h`，契约 v1.1 草案已把 §0 帧率与
   §3.5 采样率改为 45 fps（§6 变更记录）；csim/csynth/cosim 均已重跑 PASS。**仍待 A/B 会签**。
2. **性能结论（诚实）**：45 fps 对"心率/呼吸测得更细"**没有正向帮助**——
   - 心率带 0.7~3.5 Hz 在 30 Hz 下已 4 倍过采样，45 Hz 不改变能测的心率范围；
   - 呼吸带的正解是**降采样**（契约 §3.5 已写明：PS 降到 ~2 Hz），升采样方向相反；
   - 唯一收益是群延迟时间变短（688.9 vs 1033.3 ms），对趋势监测无实质意义。
3. **若坚持用 45 fps 采样**，建议 rPPG 信号在进 `fir_filter` 前先**降采样回 30 Hz（或更低）**，
   以恢复 30 Hz 系数的选择性；或接受呼吸/DC 抑制下降 ~5~16 dB 的代价。
4. **两条系数表互斥**：`fir_coeffs_q15.h` 与 `fir_coeffs_q15_45hz.h` 定义同名符号、同一 include guard，
   只能二选一包含（换表 = 换 `fir_filter.cpp`/`host_model_fir.cpp` 的 include + 重新生成黄金参考）。
5. **后续若要正式纳入契约**：走 `docs/interface.md` §6 变更流程（改 §0 + §3.5 采样率、
   重跑 csim/csynth/cosim、三方会签），**本报告不代签**。
