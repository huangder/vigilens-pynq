## 1. 本次修掉的两个测试台缺陷（**不修则 127 阶永远红**）

W5 的 127 阶档此前跑不起来，根因不在 IP，在**测试台/脚本口径不一致**：

| # | 位置 | 现象 | 根因 | 修法 |
|---|---|---|---|---|
| 1 | `fpga/run_hls.tcl` `add_files` 段 | `csim` 报 `ERROR: 契约/系数不一致 —— meta taps=127 shift=15，本工程 taps=63 shift=15` | `-DFIR_FS_60HZ` **只加给 `src`，没加给测试台**（`add_files -tb` 无条件在后面单独一句）。测试台硬编码 include `fir_coeffs_q15.h` ⇒ tb 按 63 阶推期望，IP 按 127 阶输出 | 宏同时给 src 与 tb（并把 `add_files -tb` 收进同一分支，避免重复添加） |
| 2 | `fpga/sim/tb_fir_filter.cpp` 冲激用例 | `FAIL impulse: argmax=63(exp 63) sym=0`（argmax 与 `y==ey` 都对，只有"偶对称"红） | 用例输入长度写死 `const int n = 96`，却按 `k < FIR_NUM_TAPS` 检查 `y[k]` 与 `y[N-1-k]`。N=63 时 96 > 63 刚好够；**N=127 时 `y[96..126]` 根本不存在 ⇒ 越界读**，`sym` 是随机值 | 输入长度改为 `FIR_NUM_TAPS + 32`（冲激响应长度就是 N，必须喂满才能看到尾部） |

> 两条都属于"**测试台自己错了，却表现为 IP 错**"。第 2 条尤其危险：越界读在 C++ 里是 UB，
> 换台机器/换编译器就可能"自己变绿"，把真实缺陷藏起来。

## 2. 与契约的关系（**这一档还不能对接**）

- `docs/interface.md` 现行为 **🔒 v1.1**；60 Hz 属于 **v1.6 草案（未起草）**，
  127 阶系数与 `sim/data_fir_60hz` 黄金参考是 W5 的**技术前置**，不是已签接口。
- 因此本 IP **没有进入** `board/bitstream/system_wrapper.bit`（那份 bitstream 用的仍是
  30 Hz / 63 阶的导出 IP）。**不得**据此说"板上已在 60 Hz 跑 FIR"。
- 60 Hz 落地还缺：A 线时间轴（`frame_id / fps` 的 fps 取 60）、`config.yaml` 的
  `fir_fs` 口径、v1.6 会签、BD 里替换 IP 后重综合 + 重跑 S4 门限。

## 4. 复现命令（在 `fpga/` 目录，先 `call D:\Xilinx\2026.1\Vitis\settings64.bat`）

```bat
:: 127 阶 @60 Hz：csim + csynth
set "HLS_IP=fir_filter"
set "FIR_FS=60"
vitis-run --mode hls --tcl run_hls.tcl

:: 加做 RTL cosim
set "HLS_EXEC=2"
vitis-run --mode hls --tcl run_hls.tcl

:: 63 阶 @30 Hz 回归（不设 FIR_FS）
set "HLS_IP=fir_filter"
set FIR_FS=
vitis-run --mode hls --tcl run_hls.tcl
```
