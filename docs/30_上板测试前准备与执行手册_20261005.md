## 0. 结论先说

1. **上板不欠软件**：上板前的离线工作**已经全部有脚本、有自检**（§2），要做的是**把它们跑绿并留证据**，
   不是写新算法。
2. **卡住上板的只有三件事**（都不是代码问题）：
   | # | 卡点 | 归属 | 不解决会怎样 |
   |---|---|---|---|
   | 1 | **板子通电所需的配件**（+5V DC 电源、micro-USB 数据线 ×2、micro SD） | 采购 | 板子**根本点不亮**，"完全没反应"极易被误判成板子坏了 |
   | 2 | **PS7 的 1 GB DDR3 参数**（MicroPhase 是否给 Vivado board file **未确认**） | 厂商资料 | `build_bd.tcl` 刻意 `exit 1`；**猜参数会生成一块起不来的板子** |
   | 3 | **真像素才需要的 IMX219 + MIPI**（相机、排线、IP 授权核实） | 采购 + Vivado IP Catalog | 只影响 S5；**S1~S4 不需要相机** |
3. **顺序不能乱**：**先离线全绿 → 再最小 PL 上板（不启 PS）→ 再 PS bring-up → 再 BD/bitstream → 再自检三脚本 →
   最后才接相机**。理由：一次只引入一个新变量，否则"算法错 / 链路错 / 板子坏"混在一起无法定位。
4. **第一次上板本来就不该接相机**：`dma_test.py` / `hw_sw_compare.py` 的输入是
   `fpga/sim/data/frames.bin` 这类**黄金向量**。先证明"PL 算得对"，再谈"像素从哪来"。

### 0.1 阶段依赖图

### 1.2 档位（`VIGILENS_TIER`）—— **上板最容易错的一条**

`VIGILENS_TIER` 决定帧尺寸/抽取比/灰度尺寸，**必须与实际综合进 bitstream 的那一档一致**：

| 档位 | 测量口径 | 抽取比 | 灰度工作尺寸 | 用哪套黄金参考 |
|---|---|---|---|---|
| （不设） | 640×480 | 3/5 | 384×288 | `fpga/sim/data` + `data_motion` |
| `720p60` | 1280×720 | 3/8 | 480×270 | `data_roi_720p` + `data_motion_720p60` |
| `1080p45` | 1920×1080 | 1/4 | 480×270 | `data_roi_1080p` + `data_motion_1080p45` |

> **配错档位的症状是"IP 算错了"**（比对全红），实际是环境配错。上板前先跑 `python board\hw_sw_compare.py --selftest`，
> 它会报出"`gray.bin` 能不能被本档 `GRAY_PIXELS` 整除"这类配错。
> 两档的灰度工作尺寸都固定 **480×270**、片内帧缓存仍是 **64 个 BRAM18** —— 这是档位化方案能成立的唯一理由。

### 1.3 脚本调用位置

`bringup_check.py` / `dma_test.py` / `regmap.py` 等 `import regmap`，**必须在 `board/` 目录下运行**

### 3.3 扩展口接线（JP2 子集；权威表在 `docs/12` §3）

| JP2 脚 | 信号 | FPGA 引脚 | 用途 |
|---|---|---|---|
| 3 | GPIO2_1P | **G17** | `clk_test`（PL 分频方波，1 kHz，用于**测频反证时钟**） |
| 5 | GPIO2_2P | **K14** | `uart_rx` ← OpenMV P4 (TX) |
| 7 | GPIO2_3P | **H15** | `uart_tx` → OpenMV P5 (RX) |
| 11 | VCC_5V | — | ⛔ **绝对不要接外设信号脚** |
| 12 | GND | — | ✅ 共地（必接） |
| 29 | VCC_3V3 | — | 可选用；建议**先不要**用板子给外设供电 |

**上电前必须确认的 5 件事**：
1. ☑ **共地**（JP2 pin 12）—— 不共地是最常见的"完全收不到数据"原因。
2. ☑ **TX/RX 交叉**（自己的 TX 接对方 RX）。
3. ☑ **电平 3.3V 直连、不需要电平转换**：官方手册说 BANK34 的 VCCIO 由 R208/R209/R210 决定，
   出厂焊 R208 = 3.3V。**用万用表量一下 JP2 pin 29(VCC_3V3) 与 pin 11(VCC_5V) 的区别**，
   顺手确认 R208 在位、R209/R210 不在位。
4. ☑ **绝不要把 VCC_5V（pin 11）接到外设信号脚**（会打坏 IO）。
5. ☑ **先不要用板子的 3V3 给外设供电**，让它用自己的 USB —— 少一个变量，故障好定位。

## 4. 阶段 S1：最小 PL 上板 —— 字节回环 + 1 kHz 测频（**不启 PS、不用 DDR**）

**目的**：一次只验证一件事，且每件都能单独定位故障。**这是第一次上板该做的事**，不是 Block Design。

| 验什么 | 怎么看 | 失败说明什么 |
|---|---|---|
| bitstream 能下载 | Vivado 报 `Program successful` | JTAG / 驱动 / 器件型号 |
| **PL 时钟真的是 50 MHz** | 外设侧测 `clk_test` 频率，应 **1.000 kHz ±1%** | 晶振 / 约束 / 引脚错（该设计直接用 H16 的 50 MHz，**无 MMCM**） |
| IO 电平与引脚对 | 字节能进 PL（`led[1]` 闪） | XDC 引脚错 / VCCIO 不是 3.3V / 没共地 |
| 双向通路通 | `MODE="echo"` 多数轮次逐字节一致 | TX/RX 接反 / 波特率 / 线太长 |

**要用的两个文件（都在 `board/openmv/`）**：

```
board/openmv/pl_uart_echo.v              ← PL 侧最小设计（UART 字节回环 + 心跳 + 1kHz 测频）
board/openmv/mizar_z7_openmv_uart.xdc    ← 上面那张表的引脚约束
```

**操作**：
1. Vivado 建**最小工程**（上面两个文件 + 一个 top 就是全部）→ 综合 → 实现 → 生成 `.bit`；
   **先把 `util.rpt` / `timing.rpt` 存档**（门限 1/2 要回填 `fpga/report/m3_system_budget_v1.md` §3）。
2. Hardware Manager → **Program Device**（**易失，重上电即失效**）。
3. 外设侧改 `MODE = "echo"` 运行。

**判据**：
- `clk_test` 实测 **1.000 kHz**（**这是"时钟真的对"的硬证据，比"LED 亮了"强得多**）。
- `echo` 结果：**多数轮次逐字节一致**。⚠️ **不是要求 100%** —— `pl_uart_echo.v` 刻意只做了
  1 字节暂存、**没有 FIFO**，连续满速发送时**预期会丢字节**（文件头已写明）。
  这正好用来验证上位机协议里的丢帧统计是否真在工作：`--serial` 模式的输出里应能看到
  `crc_errors` / `lost_frames` 有反应。
- 本步产出的证据归档到 `fpga/report/`（C 线目录），并回填 `m3_system_budget_v1.md`。

## 6. 阶段 S3：Block Design → bitstream（`docs/29` T9/T10）

```bat

cd /d D:\Desktop\AMD\board
vivado -mode batch -source build_bd.tcl
:: 产物 .bit/.hwh 拷到 board/bitstream/；真实资源/时序回填 m3_system_budget_v1.md 第 3 节
```

### 6.1 两个硬约束（**刻意设计，不要绕过**）

1. `build_bd.tcl` 的板级 preset 由 **`USE_BOARD_PRESET` 开关**控制，**默认 0 = 不套用 PYNQ-Z2 preset**。
   （原版曾硬编码 `tul.com.tw:pynq-z2:part0:1.0`，2026-09-23 已改。）
2. **未落实 PS7 配置时脚本会主动 `exit 1`** 并打印该做什么。原因：
   **猜错 DDR 参数会得到一块 PS 起不来的板子，症状是"完全没反应"，极易误判为板子坏了。**
   - MicroPhase 是否为 **Mizar-Z7** 提供 Vivado board file **未确认**（同厂 Z7-Lite 有）。
   - 若**没有** → PS7 的 **DDR 参数必须取自 MicroPhase 参考设计**（**不允许猜**），或手工配 PS7
     （1 GB DDR、UART、Ethernet、SD）+ 自己写 XDC。
   - ⚠️ `build_bd.tcl` 里的 `set PART "xc7z020clg400-1"` 与实物**一致，不用改**；
     `PCW_FPGA0_PERIPHERAL_FREQMHZ = 100` 也不用改。

### 6.2 C8 执行清单（来自 `m3_system_budget_v1.md` §7，让上板变成机械动作）

1. `export_design` 或直接用 IP-XACT 把 IP 加入 BD（`vitis-run` 的 `HLS_EXEC=3` 可导出）。
2. BD：PS7（使能 `M_AXI_GP0` + `S_AXI_HP0`）→ SmartConnect → 各 IP 的 AXI-Lite；DMA 的 MM2S/S2MM 经 `S_AXI_HP0`。
3. 像素链直连：`roi_statistic.video_out → rgb2gray.rgb_in`、`rgb2gray.gray_out → motion_quality.gray_in`。
4. FIR 路径：AXI4-Stream FIFO → `fir_filter.fir_in`，`fir_filter.fir_out` → 另一个 FIFO 或 DMA-B。
5. 时钟：`FCLK_CLK0 = 100 MHz` → 所有 IP 的 `ap_clk`；复位统一用 `Processor System Reset`。
6. 约束：`create_clock -period 10`；检查 BD 的 critical warnings（位宽/协议不匹配会在这里现形）。
7. 综合 → `report_utilization` / `report_timing_summary` → **把真实数字回填 `m3_system_budget_v1.md` §3**。
8. 导出 bitstream + `.hwh` 到 `board/bitstream/`，写加载器到 `board/overlay/`。
9. 按 §5 的 9 条门限逐条记录（**每条都要贴命令与输出**）。

> 📌 数据流取舍（`m3_system_budget_v1.md` §4 的推荐）：**像素链走 DMA + S2MM 回读，时间序列走 AXI4-Stream FIFO**。
> 理由：① 时间序列 60 B/s，DMA 的复杂度与资源都不划算；② 像素链保留 DMA **不只是搬运，还是证据来源**
> —— 把硬件 `rgb2gray`/`motion_quality` 的输出流回 DDR，与 A 线 NumPy 结果做**同帧逐像素比对（容差 0）**；
> ③ 两个平面物理隔离，M3 可以分步点亮。
> 带宽核对（算术）：MM2S 喂 640×480 RGB @30 fps = **27.6 MB/s**、S2MM 回读 384×288 灰度 @30 fps = **3.3 MB/s**、
> FIR 时间序列 ≈ **120 B/s** —— 对 DDR/HP 口都是零头。

### 6.3 门限 1/2（**在 Vivado 报告里判**）

| # | 门限 | 判据 |
|---|---|---|
| 1 | **装得下** | LUT ≤ 70%、BRAM ≤ 80%、DSP ≤ 70%（留出后续改动余量） |
| 2 | **时序收敛** | 100 MHz 下 **WNS ≥ 0**（`report_timing_summary`），无 critical warning |

**降级路径（真收不住时，按代价从低到高）**：

| 触发条件 | 降级动作 | 代价 |
|---|---|---|
| 时序收不住（WNS < 0） | `FCLK_CLK0` 从 100 MHz 降到 **75 MHz**（各 IP 都 ≥ 137 MHz，余量极大） | 吞吐略降，功能不变 |
| LUT 紧张 | 去掉 S2MM 回读通道 | 失去 M4 的一条硬证据 |
| DSP 紧张（FIR 占 25） | FIR 的 MAC 折叠：`#pragma HLS PIPELINE II=4` | II 上升（30 Hz 下无感），DSP 大幅下降 |
| 流深度/背压出问题 | IP 之间插 AXI-Stream FIFO / Data FIFO 做弹性缓冲 | 占少量 BRAM |
| 时间序列想再省 | FIR 改用 FIFO 直连，AXI-Lite 只留必要寄存器 | 灵活性下降 |

## 8. 阶段 S5：IMX219 + MIPI 真像素（`docs/29` T11/T12）

**为什么必须走 MIPI**：契约帧 640×480 RGB888 = **921600 B/帧**、@30 fps = **27.648 MB/s**。
OpenMV 的每条链路都装不下（UART 差 29.5×、USB full-speed 差 18~27×、SPI 仍差 2.8×），
只有有损 JPEG 能进，而它违反契约 §4.3 的**容差 0**。
Mizar-Z7 7020 版**自带 MIPI CSI 口**（15-pin 1 mm FPC，**引脚兼容树莓派摄像头**，实测 672 Mbps/lane）——
这是唯一能满足 27.6 MB/s 且**无损**的路线。**相机方案 = Camera Module 2（IMX219）。**

### 8.1 驱动与离线自检（**已完成的那一半**）

```powershell
python board/imx219_sccb_check.py        # 期望 110/110，exit 0
```

- 【已验证】`board/imx219_driver.py` + `board/imx219_sccb_check.py` 覆盖**离线能验的那一半 + 寄存器表**：
  几何 / 链路预算 / SCCB 线上字节序 / **安全阀**（寄存器表含未核实项即**拒绝下装**）/ 寄存器初始化序列。
- 寄存器初始化序列**已按 linux `imx219.c` 补齐**（`docs/27` §1.4）。
- ⚠️ **引用时不得表述成"IMX219 驱动已完成 / 相机能起来了"** —— **出图仍需硬件**（B3~B6）。

### 8.2 未闭合项（B3~B6，全部【未验证】）

| # | 事项 | 怎么做 | 5 分钟/数天 |
|---|---|---|---|
| **B3** | SCCB 从地址与地址宽度 | 上板 `i2cdetect` 扫一次 | 5 分钟 |
| **B4** | **在 Mizar 上能否出图** | 含 **3.3V / I2C / MCLK 从未量过**；先量供电与时钟再谈出图 | 数小时~数天 |
| **B5** | binning 对 **Bayer 相位**的实际影响 | **test pattern 打竖条 + 抓 raw**，与离线推导比对 | 数小时 |
| **B6** | **`raw10_unpack` 的 beat 宽度与打包形式**（**唯一的集成假设**） | **上板 ILA 抓一次**，确认握手与打包与 `raw10_unpack.cpp` 头部假设一致 | 数小时 |
| B2 | 720p60 的像素读出源 | 见 §8.3 | — |

> **B6 是本项目唯一的"集成假设"**：`fpga/src/raw10_unpack.cpp` 头部的 1 beat = 5 字节组装在 64 bit 低 40 位、
> `tkeep=0b11111` 这一假设**没有实物依据**，必须用 ILA 抓一次证实或证伪。

### 8.3 三条待决（**属 A/B/C 三方表态，不是 C 线能单独拍板的**）

1. **720p60 档的像素从哪来**（`docs/29` T1）：真机 4 个模式（640×480 / 1640×1232 / 1920×1080 / 3280×2464）
   **不含 720p**，但传感器**支持** 720p（规格书 Features：180 fps@720p special binning；NVIDIA 驱动有 720p60 模式表）。
   三条路：① 转录 720p 模式表（仅剩动作）；② 改用 **1640×1232** binned、帧率按 **41.85**（**要改契约 §0**）；
   ③ PL 新增一档 `frame_scale`。
2. **MIPI IP 授权**：厂商手册（标注 Vivado 2018.3）写 *"It requires a licence to use, but it is possible to obtain
   an evaluation licence … at no cost."*，而 `docs/10` §12.2 记【已验证】自 Vivado 2020.1 起在免费标准授权内。
   **说法冲突，必须在本机 Vivado IP Catalog 里核实**（`get_ipdefs -filter {NAME =~ "*mipi_csi2_rx*"}`），
   **不自行拍板**。
3. **不要加长 MIPI 排线**（D-PHY 高速差分，官方 200 mm 够用）。

**其他**：`board/mipi_csi2_rx_bd.tcl`（实例化 + 参数 + 数据通路 + 200 MHz 时钟）**未验证**，
需 Vivado + IP 授权 + DDR 参数 + D-PHY XDC，本机验不了。
开源先例查过（gatecat/CSI2Rx 是 MIT 但**仅数字 RX、不含 D-PHY**；Digilent/vivado-library 是 Zybo-Z7 生态）
⇒ **没有"插上就能用"的开源 MIPI CSI-2 RX**，仍走 Vendor IP + 自研后端。

## 11. 现在还"不存在"的东西（报告 / 答辩红线，防"已完成幻觉"）

| 不存在的 | 说明 |
|---|---|

| **IMX219 能不能出图** | 驱动只覆盖"离线能验的那一半" + 寄存器表；出图需硬件（B3~B6） |
| **720p60 的像素来源** | 传感器支持，但**模式表尚未转录进驱动**，且需三方选路径（T1） |

| **年龄模型的精度** | 未在本机/本场景评估过 |
| **各年龄段的疲劳基线** | 检索确认**不存在**"既带疲劳标注又带受试者年龄"的公开数据集 ⇒ 只能自建采集 |

| **血氧 / 血压 / 医疗级精度** | RGB 摄像头原理上不可靠，**一律不提供**（铁律 5） |
| **MIPI IP 授权是否可用** | 说法冲突，需在 Vivado IP Catalog 核实 |
