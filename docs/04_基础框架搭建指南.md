# 基础框架搭建指南
## 当前阶段首要任务：先搭骨架，再填算法

> 本文是**当前阶段（第 0~1 周）的唯一执行主线**。目标只有一个：
> **在最短时间内跑通一条"视频 → JSON → 网页"的端到端 stub 链路**，让三个人各自都有一个"能跑、能测、能复现"的骨架，然后再逐模块替换成真实现。
>
> 配套：分工见《02》，实现细节见《03》，工具见《06》，AI 用法见《05》。

---

## 一、什么是"基础框架"（一句话 + 组成）

> **基础框架 = 一个端到端能跑、但每个模块都是"最小可用(stub)"的闭环 + 一套可复现的工程脚手架。**

它由 6 部分组成：

| 组成 | 内容 | 为什么必须现在做 |
|---|---|---|
| 1. 目录结构 | 英文命名、符合赛制推荐目录 | 赛制硬性要求，后改成本高 |
| 2. 接口契约 | `interface.md` + `config.yaml` + JSON schema | 三线并行的唯一耦合点，早冻结早安心 |
| 3. stub 流水线 | A 读视频→出 JSON；B 收 JSON→渲染；C 最小 IP 仿真 | 先证明"链路通"，再逐个替换 |
| 4. 测试脚手架 | pytest / cocotb / 黄金参考脚本 | 让"完成"可验证，不是"看起来能跑" |
| 5. 一键复现 | README + requirements + 启动脚本 | 赛制"可复现"评分项 |
| 6. 版本与开源 | git 仓 + .gitignore + 开源协议 | 赛制要求，越早越好 |

---

## 二、为什么"先框架、后算法"

1. **消除"等别人"的依赖**：stub 让 B 线不等 A 线、C 线不等板卡，三线第 1 天就能同时开工。
2. **尽早暴露接口问题**：字段对不上、状态缺枚举这类问题，在 stub 阶段改成本极低，等算法写满再改是灾难。
3. **任何时候都有保底作品**：即使某条线卡住，骨架 + 占位数据也能凑出一个可演示、可录视频的闭环。
4. **符合赛制对"工程完整度 + 可复现"的强要求**：评委最看重"别人能否从零复现"，骨架正是复现性的载体。

## 四、三线各自的"最小骨架交付"（M1 的验收口径）

### A 线（算法）：跑通"回放视频 → 契约 JSON"

最小可交付 = 下面这条链在 stub 状态跑通：

```
VideoCapture(回放视频) → 人脸框(可有) → EAR(只此一个真指标) → 契约 JSON → 打印/写文件
```

- `capture.py`：读视频，逐帧 yield。
- `face_landmark.py`：先接 MediaPipe（它本身很成熟，不算"算法工作量"，属于框架内）。
- `behavior_metrics.py`：**只实现 EAR + 眨眼计数**，PERCLOS/MAR/头姿先返回占位值。
- `decision.py`：**先写死返回 `normal`**，规则下阶段再填。
- 验收：对同一段回放视频连续跑两次，输出的 JSON 字段完整、数值一致。

### B 线（前端）：跑通"Mock JSON → 网页渲染"

最小可交付 = 浏览器里能看到一个六态齐全、用 Mock 数据驱动的仪表盘。

- `mock.py`：按契约 schema 生成合理假数据（眨眼、PERCLOS、状态随机但合理）。
- `websocket.py`：每秒推送一帧 mock JSON。
- `index.html + app.js`：视频占位区 + 指标卡 + 六态状态灯 + 一条滚动曲线 + 事件日志。
- 验收：断网/关后端时页面显示"连接中断"，六种状态都能切出来看。

### C 线（FPGA）：跑通"最小 IP 仿真 + 综合"

最小可交付 = 一个功能**简化到极致**的 IP 通过 C 仿真，并出综合报告。

- 把 `roi_statistic` 先简化为：对输入像素流做"计数 + 累加"（不切 ROI、先不做均值），验证 HLS 工具链 + AXI-Stream 接口范式走得通。
- 配一个 Python/NumPy 黄金参考，C 仿真结果与之一致。
- 验收：C 仿真通过 + 综合无 ERROR，出 LUT/FF 报告。

> 关键心态：**M1 只求"链路通 + 工具链通"，不求功能全。** 算法深度留给 M2 以后（见《03》）。
