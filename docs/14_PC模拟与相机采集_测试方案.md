# 第一部分：框架

## 0. 这份方案要回答的三个问题

| # | 问题 | 谁能回答 |
|---|---|---|
| Q1 | **算法链路**在 PC 上是否自洽、可复现？ | **轨 A**（纯 PC，零硬件） |
| Q2 | **真实采集**这一路能给什么分辨率/帧率/画质？ | **轨 B**（UVC）与 **轨 C**（MicroPython） |
| Q3 | 采集到的数据**够不够支撑可信的测算**？ | 轨 B/C 产出 + 轨 A 的算法（低帧率偏差评估） |

> ⚠️ **本方案不回答**"FPGA 算得对不对" —— 那需要 `bitstream`，属于 `docs/11` 的 L8~L10，
> 而且**输入的黄金向量是离线的 `fpga/sim/data/frames.bin`，本来就不接相机**（`board/openmv/README.md` §3.2/§T4）。

## 1. 三条轨与互斥关系（**这是全篇最该先看懂的一张图**）

```
                  ┌─ 轨 A：PC 模拟（零硬件，随时可做，可重复）
                  │     合成帧 / 现成视频 / 有脸 mp4 → 算法 → 契约帧 → 网页
                  │     ★ 验"算法与链路"，不验"采集"
                  │
 采集源 ──────────┼─ 轨 B：UVC 采集（刷 uvc.bin）
                  │     OpenMV = 标准 UVC 摄像头 → 序号喂进管线 → 网页有真实画面
                  │     ★ 验"采集→网页"整条，但【代码跑不了】
                  │
                  └─ 轨 C：MicroPython 能力矩阵（不刷固件）
                        OpenMV IDE 跑 openmv_capture_test.py → 分辨率/帧率/内存表
                        ★ 验"相机能力"，但【网页看不到画面】

  ⚠️ 轨 B 与轨 C 共用同一台相机，靠"刷固件"切换 —— 不可兼得，一次只能选一条
  ⚠️ 轨 A 与 B/C 可并行（轨 A 不占相机）
```

**推荐顺序**：轨 A（先做，验证 PC 侧基线）→ 轨 C（**优先**，因为缺数据的正是它）→ 轨 B（演示）。

### A1 合成源：算法链路 + 六态【已验证】

```powershell
python backend/run_pipeline.py --source synthetic --pattern blink --seconds 30 --stub `
    --json metrics/logs/last.json `
    --jsonl metrics/logs/stream.jsonl `
    --csv metrics/logs/metrics.csv
```

`--pattern` 可换 `blink` / `yawn` / `still` / `turn`。

**今天实测**（`--seconds 25`）：处理 **750 帧 / 墙上 1.11 s**，状态分布
`normal=499  unreliable=138  fatigue_risk=113`，逐秒打印 `EAR / PERCLOS / Q / 状态 / 理由`。

**判据 / 必须知道的三条**：

1. 退出码 0，末帧状态属六态之一；
2. 打印里有 **`关键点来源: stub`** → **EAR/MAR 是占位几何量，不得作为算法结果引用**（铁律 1）；
3. **合成帧源没有像素**（`SyntheticImage` 只有 `.shape` + 亮度标量），所以它**验不了画面**。

### A2 网页（合成源）：验指标通道【已验证】

```powershell
python metrics/scripts/run_demo.py --source synthetic --seconds 25 --port 8012 `
    --csv metrics/logs/demo_syn.csv --json metrics/logs/demo_syn_last.json
```

**判据**：浏览器打开脚本打印的网址 → **数字/曲线/状态在动**（契约通道 `POST /api/ingest` → `/ws`）。

**今天实测的两个坑**：

1. 管线会主动关掉画面推送，原文：
   `[warn] 帧源是合成帧，没有真实像素 —— 已关闭 --push-video（网页会显示占位画面）。`
   ⇒ **网页画面区是占位，不是真实画面**；
2. 但 `run_demo` 的横幅**无条件**打印 `旁路画面: http://…/video.mjpg`
   ⇒ **别被横幅骗**，以 `[warn]` 行和 `/api/video_status` 为准。

> ⚠️ 一定显式给 `--csv`：`run_demo` 默认写 `metrics/csv/demo_metrics.csv`，而那份已经是 **1.01 GiB**。

### A3 真实画面 + mediapipe（**零硬件**，强烈建议先做这条）【已验证】

```powershell
python metrics/scripts/run_demo.py --source metrics/logs/_video_bypass_clip.avi --loop --port 8011 `
```

> 这段 avi（640×480 MJPG，45 帧）由旁路画面检查脚本生成：
> `python metrics/scripts/check_video_bypass.py`（它的 mtime 会随 `check_all` 一起被刷新）。
> 内容是深灰背景 + 一条来回移动的色块 —— **里面没有人脸**。

**今天实测**：

| 观测 | 结果 |
|---|---|
| `帧源` | `file:_video_bypass_clip.avi 15.0fps 45 frames` |
| 关键点 | **`[face_landmark] 使用 MediaPipe FaceMesh（478 点）`** → `landmark_source = mediapipe` |
| 旁路画面 | `投递 45 / 编码 4 / 送达 4 / 丢弃 41` |

**判据 / 结论边界**：
- ✅ 能证明：**「真实像素 → 旁路画面 → 网页」+「mediapipe 真在跑」** 都通；
- ❌ 不能证明：算法在真脸上算得对（没有人脸 → 全 `unreliable`，这是**质量门控在正常工作**）。

**停**：`Ctrl-C`（`--loop` 是**无限**重跑；想自动退就用 `--exit-when-done` 且**别加** `--loop`）。
