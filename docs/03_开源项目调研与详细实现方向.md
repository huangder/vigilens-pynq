## 二、A 线：算法 / 后端 —— 详细实现方向

### 2.1 技术选型（先定，避免反复横跳）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 人脸关键点 | **MediaPipe FaceMesh（468 点）** 主力，dlib（68 点）对照 | 免编译、快、自带 3D 坐标；dlib 仅用于交叉验证眨眼计数 |
| 视频输入 | OpenCV `VideoCapture`，**优先文件回放** | 回放可复现，摄像头作为现场入口 |
| 头姿 | OpenCV `solvePnP` + MediaPipe 3D landmark | 无需标定相机，误差够用 |
| 信号处理 | NumPy + SciPy（`butter`、`rfft`） | 带通滤波与频谱峰值 |
| rPPG | **先手写绿色通道法**，再用 open-rppg 对照 | 手写可解释、可移植到 FPGA 对比；open-rppg 当"参考设备" |
| 配置 | YAML（`config.yaml`）统一存阈值 | 阈值不散落代码（方案已要求） |

### 2.2 各指标实现细节（写代码前先读）

**① 眨眼 / 闭眼 / PERCLOS**

- 眼关键点：MediaPipe 左眼 6 点索引 `[33,160,158,133,153,144]`，右眼 `[362,385,387,263,373,380]`（p1 到 p6）。
- 公式（Soukupová & Čech 2016）：
  `EAR = (|p2-p6| + |p3-p5|) / (2·|p1-p4|)`
- 状态机：`OPEN → CLOSING → CLOSED → OPEN`；连续 ≥3 帧低于阈值才算 CLOSED（去抖）。
- 初始阈值：dlib 常用 `0.21`；**MediaPipe 需实测重新标定**（一般 0.20~0.25），用你录的 4 段视频标一次。
- 输出：眨眼次数、眨眼频率（次/分）、平均/最大闭眼时长、`PERCLOS = 窗口内闭眼帧数 / 有效帧数`（窗口 30s）、长闭眼事件数。

**② 打哈欠（MAR）**

- 嘴部：上下唇距离 / 嘴角距离（MediaPipe 用上下唇中点 `13/14` 与嘴角 `61/291`，或取唇部多对点）。
- 阈值 `MAR ≈ 0.6~0.7`，且持续时间 `>800ms` 才算一次哈欠；用"嘴部稳定性 + 头姿约束"过滤说话/咳嗽误判。

**③ 头部姿态**

- 用 MediaPipe 自带 3D 关键点 + `cv2.solvePnP` → 旋转向量 → `cv2.Rodrigues` → yaw/pitch/roll。
- 姿态阈值（建议）：`|yaw|>25°`、`|pitch|>20°` 触发"请调整姿势"提示，用于人脸可见率辅助判断。

**④ 运动质量 / 光照质量 / 人脸可见率**

- 运动：相邻帧灰度差分总和（与 C 线 `motion_quality` 用**同一口径**，便于软硬件比对）。
- 光照：ROI 灰度均值 + 饱和像素比例。
- 人脸可见率：人脸框是否出界 + 关键点置信度。

**⑤ rPPG 心率（增强项，最后做）**

- 流程：面部 ROI（额头/脸颊，避开眼嘴）→ 每帧 G 通道均值 → 30s 滑窗 → 去直流/归一化 → `0.7~3.5Hz` 带通 → `rfft` 峰值 → BPM。
- **必须配套质量门控**：主峰突出度不足、BPM 跳变过大时，输出 `hr_bpm=null, hr_conf=低`。
- 对照：open-rppg 跑同一段视频，写进报告作为参考。

**⑥ 呼吸率（增强项）**

- 胸部/肩部 ROI → 帧间位移或亮度变化 → `0.1~0.5Hz` 带通 → 周期检测 → 次/分；人脸可见时可靠性下降，标注为扩展。

**⑦ 规则融合（decision.py）**

```python
if face_visible < 0.7:        status = "adjust_posture"
elif quality.overall < 0.6:   status = "unreliable"
elif perclos > 0.25 and yawn >= 1:  status = "fatigue_risk"
elif long_close >= 1:         status = "fatigue_risk"
else:                         status = "normal"
```

每条建议带 `reason`（"闭眼比例上升、连续打哈欠，且信号质量良好"），阈值全部来自 `config.yaml`。

## 四、C 线：FPGA / HLS —— 详细实现方向

### 4.1 工具链与接口范式

- 工具：**Vitis HLS 2026.1**（推荐）或 2025.2；先跑 `Vitis-HLS-Introductory-Examples` 锁定环境。
- 像素流接口范式（直接套 Vitis Libraries Vision）：
  - 输入/输出：`hls::stream<ap_axiu<24,1,1,1>>`（RGB888，`TUSER` 帧头、`TLAST` 行末）
  - 控制：`#pragma HLS INTERFACE s_axilite bundle=ctrl`（ROI 坐标、阈值、启动/完成）
  - 性能：`#pragma HLS PIPELINE II=1`，数组 `#pragma HLS ARRAY_PARTITION complete`
- 定点化：像素 8bit、累加 32bit、FIR 系数 Q15；**精度决策写进 `interface.md`**，A 线黄金参考按同一精度实现。

### 4.2 三个 IP 的具体方案

**IP-1 `roi_statistic`（首选，最难出错的第一个）**

- 输入：像素流 + ROI 坐标（左上/右下，经 `s_axilite` 配置）。
- 处理：落在 ROI 内的像素，累加 `sum_r/sum_g/sum_b` 并计数 `count`；帧末输出 `{sum_r,sum_g,sum_b,count}` 和均值。
- 用途：为 rPPG 和图像质量提供时间序列，**替代 PS 逐像素扫描**。
- 黄金参考：A 线用同一 ROI 坐标做 NumPy 累加，逐帧比对。

**IP-2 `motion_quality`（次选）**

- 输入：当前帧 + 上一帧灰度像素（需一行/一帧缓存，BRAM）。
- 处理：逐像素 `|cur - prev|` 求和 `diff_total`，与阈值比较统计 `motion_ratio`。
- 用途：运动质量评分，屏蔽不可靠测量。
- 黄金参考：A 线 OpenCV `absdiff` 结果比对。

**IP-3 `fir_filter`（可选，加分）**

- 输入：时间序列流（如 ROI 均值序列）。
- 处理：固定阶数 FIR 带通（0.7~3.5Hz 对应采样率换算系数）。
- 用途：硬件滤波，与 PS `scipy.signal.lfilter` 比对延迟/CPU 占用。

### 4.3 上板链路（后期，此时才需要板卡）

- Block Design：Zynq PS + AXI DMA + 自研 IP（AXI-Stream）。
- PYNQ：`Overlay('xxx.bit')` + `allocate` DMA 缓冲 + `register_map` 配置 → 调用。
- 软硬件一致性：同一输入，PL 结果 vs A 线软件结果，记录延迟/CPU 占用/吞吐对比。

## 五、三条线接口契约（深化，冻结后不可随意改）

### 5.1 A ↔ B：指标 JSON（WebSocket）

已在 `02` 文档给出完整 schema，这里只强调三个易错点：

1. `status` 只能是 6 个枚举值，B 线在 B1 阶段就要全部支持；
2. `vital.hr_bpm` 允许 `null`，B 线必须优雅渲染"暂无"；
3. `ts`/`frame_id` 必须递增，供前端断点重连时对齐。

### 5.2 A ↔ C：黄金参考对齐（软硬件一致性的关键）

| IP | A 线黄金参考 | C 线输出 | 比对口径 |
|---|---|---|---|
| `roi_statistic` | NumPy 同一 ROI 累加 | `{sum_r,sum_g,sum_b,count}` | 定点位宽一致、逐帧一致 |
| `motion_quality` | OpenCV `absdiff` 求和 | `{diff_total,motion_ratio}` | 同一帧对、同一阈值 |
| `fir_filter` | `scipy.signal.lfilter` | 滤波序列 | 同一系数、容差内 |

> 核心：**C 线全程离线验证"硬件算得对"，靠的是 A 线这份软件黄金参考，而不是等板卡。**

## 八、各线开发工具与提效 Skill（**原《06 各线开发工具与 Skill 调研》已并入本节**，2026-09-27）

> 目标：给三条线分别配"能立刻省时间的工具"，并区分三件事——
