## 1. 这次修掉的 4 个**真缺陷**（都属于"静默错"这一类）

> 共同点：**不会报错、不会崩、看着自洽**，但结果悄悄是错的。
> 这也是为什么它们能在仓库里存活若干轮 —— 只有"逐字节比对"或"档位一变"才会暴露。

### 1.1 `bayer_demosaic.cpp` 输出字节序写成 BGR 【已验证】

- **现象**：csim 的 `corner clamp` 期望 `(255,128,64)`，实得 `(64,128,255)` —— **R 与 B 恰好互换**。
- **根因**：`q.data = (to8(R) << 16) | (to8(G) << 8) | to8(B)` —— R 跑到 `bits[23:16]`，那是 **BGR**。
  而**同一个文件的注释**、**测试台的解码**（R=bits[7:0]）、**`docs/19` §6 的 "byte0=R"**、
  以及**下游消费方**（`rgb2gray.cpp:100` 的 `R=[7:0]`、`roi_statistic.cpp:87` 的 `p.data(7,0)`）
  **全都要求 R 在 byte0**。相位与插值本身是对的。
- **为什么危险**：**不会编译报错**。`rgb2gray` 会把亮度按 `77*B + 29*R` 算，全链条悄悄错。
- **改法**：把 R 放到 `bits[7:0]`、B 放到 `bits[23:16]`（3 行）。
- **验证**：`Layer 1: 3/3`（`(0,0) -> R=255 G=128 B=64`、`ref_bad=0`）、`Layer 2: 5/5`、**逐字节 0 不符**、
  `RESULT: PASS`、Fmax 142.05 MHz。

### 1.2 `tb_frame_scale.cpp` 的 "aspect check" 是**编译期恒假断言** 【已验证】

- **根因**：`(960u*3u == 640u*2u*2u) && (720u*3u == 480u*2u*2u)`
  → `2880 ≠ 2560`、`2160 ≠ 1920`，**两边全是常量** ⇒ 该断言**永远 FAIL**，且与同式的 `ow == 640`
  自相矛盾（`960*3/4 = 720 ≠ 640`）。
- **含义**：这条检查**从来没有在测任何东西** —— 它报 FAIL 不含任何关于 IP 的信息。
- **改法**：换成与 `host_model_scale.cpp` / `gen_scale_vectors.py` 同一条比例恒等式
  `out*DEN == in*NUM`（用已有宏，避免再漂）。
- **验证**：修后 `Layer 1: 3/3`、`Layer 2: 5/5`、`RESULT: PASS`，
  并首次拿到该 IP 资源：LUT 2282 / FF 2479 / BRAM 0 / DSP 3 / Fmax 151.68 MHz / II=1。

### 1.3 `board/regmap.py`：帧率口径冲突 + 灰度尺寸写死 【已验证】

- **① 帧率**：`FPS = 45`，而 `config.yaml` 是 `fps_nominal: 30`。
  仓库里**同时存在 45 / 30 / 60**（v1.1 冻结 45、v1.2 草案 30、用户新选两档 60/45），
  硬编码哪个都会让上板时间换算整体偏（45/30 = **1.5 倍**）。
- **② 灰度尺寸**：`GRAY_W/GRAY_H` 写死 **384×288**，而 v1.5 两档是 **480×270**。
  更糟的是那份自检是"**常量对常量**"（左右都写死）⇒ **在任何档位下都自洽**，
  **档位一改就自洽地错**。
- **改法**：引入档位表，`FRAME_W/H`、`DECIM_*`、`GRAY_W/H`、`FPS` 全部**按档位推导**
  （`VIGILENS_TIER` 选，缺省 = 既有 640×480，**行为不变**）；
  自检改为"左值 vs 独立算出的具体数"，并新增两条档位自洽断言。
- **验证**：三档 `--selftest` 全 PASS；推导值与**真实 csim 输出一致**（384×288 / 480×270 / 480×270）。

### 1.4 `board/bringup_check.py`：写回期望值写死 640/480/384/288 【已验证】

- **根因**：`("mot.width", mot, R.MotionQuality.width, 384)` 这类**字面量期望值** ——
  与 1.3 是同一类缺陷（档位化后会与真正下载的 bitstream 口径不一致，且看着自洽）。
- **改法**：全部改为取自 `regmap` 的推导值。
- **验证**：新增 `--selftest`（离线），三档全 PASS，且 `next_pow2(GRAY_PIXELS)` 三档都是 **131072 = 2¹⁷**
  —— 正好卡在 BRAM 台阶上，这就是 v1.5 的技术要点。

### 4.1 一条值得记的坑：dot-source 会**静默覆盖同名变量** 【已验证】

`omv_stream_bridge.ps1` **自己也有** `param([switch]$SelfTest)`。**dot-source 会在当前作用域
执行被加载脚本的 param 块** ⇒ 父脚本的 `$SelfTest` 被重新绑定为 `$false`，
于是 `-SelfTest` **被静默忽略**（第一次实现就是这样：跑完自检还照样启动 api.py 跑整轮演示）。
桥接脚本只对**自己**有防护（`$MyInvocation.InvocationName -ne '.'`），**父脚本的变量照样被覆盖**。
**判据**：任何 dot-source 它的脚本，**不要在 dot-source 之后再读 `$SelfTest`**。

## 7. 怎么复现本报告里的每一个数字

### 7.0 档位数据已入仓（2026-10-01 归位，SHA256 校验一致）

各目录都有 `README.md`（写明了应有文件、期望大小、生成命令、已验到哪一层）。用
`fpga\promote_tier_data.ps1` 从仓库根临时目录归位；它会**逐文件校验 SHA256**，
不一致就报 FAIL —— 因为 HLS 测试台是**容差 0** 比对，"数据被改坏了"会伪装成"IP 算错了"。

| 目录 | 内容 | 大小 |

| `fpga/sim/data_motion_1080p45/` | 1080p45 档 gray/motion 黄金参考（480×270） | 60.6 MB |
