## 2. L0：总入口（**先跑这一条**）

```powershell
# 第 0 步（Windows PowerShell 必做）：载入会话环境
#   它会切到仓库根 + 把 .venv\Scripts 排到 PATH 最前，之后直接敲 python 即可
. .\env.ps1

# 总入口
python metrics/scripts/check_all.py
```

> ⚠️ **不点源 `env.ps1` 就必须自己在仓库根执行**。裸相对路径 `.venv\Scripts\python.exe`
> 只在仓库根有效；在别处会报 `无法加载模块 ".venv"` —— 那个报错**与真实原因（路径没找到）无关**。
> 详见 §5 环境坑表第 1 行。
>
> ⚠️ `.venv/` 在 `.gitignore` 里，**新克隆的仓库不会带它**：
> `python -m venv .venv` → `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`。

**它跑什么**：环境依赖 → A 线总入口（pytest / 模块自检 / 确定性 / 黄金参考 / M2）
→ B 线专项 → 7 个工具自检 → 语法检查 → 就绪状态。

**预期输出（本机真实结果 2026-09-24）**：

```
[环境] 10/10 通过
[A 线] 1/1 通过
[B 线] 3/3 通过
[工具自检] 7/7 通过
[语法] 2/2 通过
...
回归结论：✅ 全部通过（PASS 21 / FAIL 0，用时 56.0s）
```

**判据**：`FAIL 0` 且**退出码 0**。

> ⚠️ **两类结果要分开读**（这是 `check_all.py` 刻意设计的）：
> - **回归测试**（PASS/FAIL）—— 代码与契约行为，坏了就是坏了，**计入退出码**
> - **就绪状态**（INFO）—— 缺素材/缺板卡/缺工具链，是"**还没到那一步**"而不是"坏了"，**不计入退出码**
>
> 典型例子：`check_p4_readiness` 在没有 4 段真实视频时返回 1。那是**预期状态**，
> 如果把它算成失败，总入口就永远是红的，没人会再看它。

**失败排查**：
| 现象 | 先查 |
|---|---|
| `依赖 numpy FAIL` | `.venv` 没建好 → 见 §5 环境坑 |
| `A 线 ... FAIL` | 单独跑 `check_a_line_all.py` 看是 A~E 哪一段红 |
| `B 线 ... FAIL` | 端口被占？单独跑对应脚本看详情 |
| 退出码非 0 但汇总显示 PASS 0 FAIL | 不可能是这样；若真出现，看是不是被 `\| Select-Object` 截断管道导致的假退出码 |

## 3. 分层详细步骤

### L1 契约与跨语言一致性（✅ 已跑通）

**为什么单独列**：这是**唯一能防止三线各写一套**的检查。

```powershell
python -m pytest -q                        # 期望 78 passed
node frontend/mock.js --selftest                             # 期望 "ok": true
python metrics/scripts/check_frontend_wiring.py   # 期望 前端接线检查：通过
node frontend/mock.js --limit 6 > metrics/logs/_js_frames.jsonl
python metrics/scripts/check_frontend_contract.py metrics/logs/_js_frames.jsonl
                                                             # 期望 跨语言契约检查：通过
python metrics/scripts/check_b_line_thresholds.py # 期望 4/4
```

**判据与失败含义**：

| 命令 | 期望 | 失败说明什么 |
|---|---|---|
| `pytest` | `78 passed`（**只增不减**） | 契约被改坏、引入了非确定性、或新增功能没带测试 |
| `--selftest` | `"ok": true` | JS 的 mock 与校验器不自洽 |
| `check_frontend_wiring` | 通过 | `app.js` 引用了不存在的 DOM id ——**症状是页面不报错、区域空白** |
| `check_frontend_contract` | 通过 | **A 的 Python 与 B 的 JS 对同一份契约判断不一致** —— M2 集成必炸 |
| `check_b_line_thresholds` | 4/4 | `config.yaml` → `/api/status` → 前端兜底副本，三处漂移 |

> ⚠️ **`pytest` 基线"只增不减"**：新增功能要带测试，但**不许为了让基线好看而删测试或放宽断言**。
> 沿革：49（09-10）→ 65（09-15）→ **78（09-16）**。

### L2 A 线数据链路（✅ 已跑通）

**测的是**：帧源 → 关键点 → 指标 → 质量门控 → 决策 → 契约 JSON 的整条链，以及**确定性**。

```powershell
# 合成帧源（不需要摄像头、不需要 OpenCV）
python backend/run_pipeline.py --source synthetic --pattern blink `
    --seconds 30 --stub `
    --json metrics/logs/last.json --jsonl metrics/logs/stream.jsonl --csv metrics/csv/metrics.csv `
    --summary metrics/logs/summary.json
```

**判据**：
1. **退出码 0**，末帧状态属六态之一；
2. **确定性**：同一命令跑两次，末帧 JSON 与 CSV **逐字节相同**（这是《02》A3 的验收口径）；
3. summary 里 `landmark_source` 明确写出是 `stub` 还是 `mediapipe`。

`--pattern` 可选 `blink` / `yawn` / `still` / `turn`。

> ⚠️ **`landmark_source` 是最容易读错的一个字段**：为 `"stub"` 时 EAR/MAR 是**占位几何量**，
> 该次运行的指标**不得作为算法结果引用**。合成帧源会自动用 stub（因为合成图里没有人脸）。

### L6 OpenMV 图像采集测试（⚠️ 待硬件）

**需要**：OpenMV Cam H7 + micro-USB 线。

**第 1 步：能力矩阵**（把 `board/openmv/openmv_capture_test.py` 放到 OpenMV 的 U 盘根目录
—— 它**自包含**，不需要 `vigilens_link.py`；用 OpenMV IDE 或 **VSCode 的 OpenMV 扩展**
打开、改 `MODE = "matrix"`、点运行）

```python
MODE = "matrix"
```

**判据 / 这一步买到什么**：

| 列 | 定论什么 |
|---|---|
| `fps均值` / `fps中位` | 契约要 30fps，一眼看出差多少 |
| **`最慢帧`** | 最坏情况的采样间隔（运动/眨眼检测关心的是它，不是平均值） |
| `B/帧` vs `理论B` | 两者差很多 → 实际生效的分辨率/格式与请求的不是一回事 |
| **`mem可用`** | `gc.mem_free()` 实测。契约要 640×480 **RGB888 = 921,600 B/帧**，而 H7 只有 1 MB SRAM —— **能不能整帧装下，看这列就定论** |

**第 2 步：无损落盘**（`MODE = "dump"`，`CHOSEN_*` 填第 1 步可用的最好组合），
逐帧回读校验 + 记录 `pixel_samples`（RGB565 位扩展的对拍样本）。

**第 3 步：PC 侧转契约布局**
```powershell
# 先把 dump 目录设成变量（换成你自己的路径）—— 用变量而不是 <尖括号>，
# 因为 PowerShell 里 < 和 > 是保留运算符，带尖括号的命令**没法直接复制粘贴**。
$dump = "metrics\logs\openmv_dump"

python board/openmv/raw_to_contract.py $dump --info
python board/openmv/raw_to_contract.py $dump --calibrate
python board/openmv/raw_to_contract.py $dump `
    --out metrics/logs/openmv_frames.bin --report metrics/logs/openmv_convert.json
```
**判据**：`--calibrate` 能**唯一判定** RGB565 位扩展公式；
输出字节数 = 帧数 × W × H × 3；通道顺序 `c=0→R`。

> ⚠️ **JPEG 是死路**：源格式为 JPEG 时转出的 RGB888 **不能**作 C 线黄金参考（契约 §4.3 要求容差 0），
> `raw_to_contract.py` 会明确拒绝转换。

### L7 真实视频 / 相机喂 A 线（⚠️ 待硬件）

**最快的一条路：OpenMV 刷 `uvc.bin` → 变成标准 UVC 摄像头 → 零代码就能用。**

```powershell
# 一条命令：起服务 + 起管线 + 开浏览器（含旁路真实画面）
python metrics/scripts/run_demo.py --list          # 第 1 步：找出摄像头序号
python metrics/scripts/run_demo.py --source 0      # 第 2 步：把 0 换成上一步打印的序号
```

> ⚠️ **不要把 `--source <序号>` 照抄进 PowerShell** —— `<` `>` 在 PowerShell 里是**保留运算符**，
> 会报 `"<"运算符是为将来使用而保留的`。`--list` 会直接打印一行"用法：--source N"，
> **把那个数字填进去**即可。

**判据（三条，缺一不可）**：
1. 服务起来、网页打开、指标在动；
2. **`landmark_source` 必须是 `mediapipe`** —— 若是 `stub`，这批数据只能证明"链路通"，
   **不能写进任何指标结论**；
3. **`distinct_frames ≈ frames`** —— 若 `distinct_frames == 1`，说明拿到的是**冻结画面**，
   那个"帧率"是假的（`host_capture_test.py` 会打警告）。

**低帧率影响评估**（拿到真实帧率 F 之后必须做）：

```
最短可检出闭眼 = min_close_frames / F = 3 / F
  F=10 → 300 ms   （严重：正常眨眼 100~400 ms，会漏掉一大截）
  F=20 → 150 ms   （仍偏漏）
  F=30 → 100 ms   （合格）
```
若 F < 20，必须在报告里写明；要不要改 `config.yaml` 的 `min_close_frames` 需要依据 + 公告。

### L8 PL 首次上板：字节回环 + 时钟自证（⚠️ 待硬件）

**这一步刻意不需要 PS、不需要 DDR** —— 用板载 USB-JTAG 直接下载，一次只验一件事。

**准备**：Vivado 建最小工程，加两个文件就是全部：
- `board/openmv/pl_uart_echo.v`（UART 字节回环 + 心跳 + 1 kHz 测频输出）
- `board/openmv/mizar_z7_openmv_uart.xdc`（引脚约束）

综合 → 实现 → 生成 bitstream → **先把 `util.rpt` / `timing.rpt` 存档** → Hardware Manager 下载。

**接线**：见 `docs/12_硬件清单与接线文档.md` §4.3（只接 3 根线 + 共地）。

**判据**：

| 验什么 | 怎么看 | 失败说明什么 |
|---|---|---|
| bitstream 能下载 | Vivado 报 Program successful | JTAG/驱动/器件型号 |
| **PL 时钟真的是 50 MHz** | OpenMV 侧测 `clk_test` 频率，应 **1.000 kHz ±1%** | 晶振/约束/引脚错 |
| IO 电平与引脚对 | 字节能进 PL（`led[1]` 闪） | XDC 引脚错 / VCCIO 不是 3.3V / 没共地 |
| 双向通路 | OpenMV `MODE="echo"` 多数轮次逐字节一致 | TX/RX 接反 / 波特率 / 线太长 |

> ⚠️ **`echo` 不是要求 100%**：`pl_uart_echo.v` 刻意只做 1 字节暂存、没有 FIFO，
> 连续满速时**预期丢字节**（文件头已写明）。这正好用来验证丢帧统计真的在工作。

### L9 PS bring-up（⚠️ 待硬件）

**需要**：Mizar-Z7020 + **+5V DC 电源**（不是 micro-USB 供电）+ micro-USB 线 + 网线。

| 步骤 | 判据 | 不对怎么办 |
|---|---|---|

## 5. 已知环境坑与噪声（不是代码问题，别浪费时间）

| 现象 | 原因 | 处理 |
|---|---|---|
| **`无法加载模块 ".venv"`** / 提示 `Import-Module .venv` | **不是缺模块** —— 是当前目录不是仓库根，裸相对路径 `.venv\Scripts\python.exe` 没找到，PowerShell 把它当成了"加载模块"。**报错信息与真实原因完全无关** | `. .\env.ps1`（自动切到仓库根）；或先 `cd` 到仓库根；或用绝对路径 |
| **`. .\env.ps1` → 不是可识别的命令** | 该文件在 2026-09-24 之前是**本机文件、不在仓库里**，新机器照文档做必然失败 | ✅ 已补为可提交的通用脚本；`git pull` 后即可用 |
| **`.venv` 不存在** | `.venv/` 在 `.gitignore`（第 39 行），不随仓库分发 | `python -m venv .venv` + `pip install -r requirements.txt` |
| **`.ps1` 改完语法莫名报错**（`Unexpected token '}'`） | **PowerShell 5.1 读无 BOM 的 `.ps1` 会按 GBK 解码**，中文注释被解坏即破坏语法 | `.ps1` 存成 **UTF-8 with BOM**（`.md` / `.py` 不需要） |
| **`"<"运算符是为将来使用而保留的`** | 文档里的占位符（`<序号>`、`<dump目录>`…）被**照抄**了。PowerShell 里 `<` `>` 是**保留运算符**，带尖括号的命令**没法复制粘贴执行** | 把占位符换成实际值；本文件已改用「具体示例 + 注释」或 `$变量` 写法。**任何 `<...>` 都不要直接执行** |
| `python -m pytest` → `No module named pytest` | 系统 Python 没装 | 先 `. .\env.ps1` |
| `PyYAML 可用: False` | 没装 PyYAML | **无需处理**：`backend/config.py` 降级为内置解析器读同一份 `config.yaml` |
| 脚本中文乱码 | 控制台 GBK | 已内置 `console.enable_utf8_console()`；用 Windows Terminal / VS Code |
| **matplotlib 的 atexit 噪声** | mediapipe 会 import matplotlib，沙箱下默认缓存目录不可写 | `check_all.py` 已把 `MPLCONFIGDIR` 指到 `metrics/logs/_mplcache`；**其它入口仍会有这段噪声，它是无害的** |
| pytest 报 `WinError 5` | 本机工作区被索引进程瞬时抓句柄 | 已知环境抖动，**不要改期望值去凑绿**；见 `docs/interface.md` §5.2.1 |
| csim 报 `Win32 error 5` | 受限沙箱跑不了命名管道 | **不是代码问题**，请在完整权限终端跑 |
| 用 `\| Select-Object -First/-Last` 包住脚本时退出码变 1 | 管道提前关闭 → 上游进程被杀 | 要判退出码就**不要**接管道，或把输出重定向到文件 |
