### 1.1 中英文名称对照（按场合选用）

| 场合 | 名称 |
|---|---|
| **中文规范全称**（报名表 / 报告封面 / 官方材料） | **基于摄像头与 FPGA 的无接触疲劳与生命体征趋势监测终端** |
| **中文简称 / 产品名**（答辩 / PPT / 视频 / 口头） | **知倦** |
| **英文全称**（决赛海报 / 开源仓库描述 / 论文式标题） | **VigiLens: A Trust-Aware Contactless Fatigue Monitoring Terminal with FPGA-Accelerated Vision Preprocessing** |
| **英文简称 / 仓库名** | **VigiLens**（仓库目录 `vigilens/`，全小写） |
| **一句话标语（Slogan）** | **先判断能不能测，再决定测出什么。** / *Know when to trust the measurement.* |

> 中文规范全称用于**合规与评审可识别性**，产品名"知倦"用于**记忆点与传播**。所有材料首次出现时按"中文全称（知倦 / VigiLens）"格式写一次，之后统一用简称，三份材料（报告、PPT、视频）口径必须一致。

### 1.2 命名理由

| 设计点 | 说明 |
|---|---|
| `Vigi` = Vigilance（警觉/值守） | 直接指向主场景"长时间学习 / 值守"，也避开"medical / diagnosis"这类医疗敏感词 |
| `Lens` = 镜头 | 点明"只用摄像头、无接触"的输入形态，且是评委一眼能懂的词 |
| `Trust-Aware` | 把**信号质量门控**写进标题，直接承载《01》第五节方向 1 的差异化卖点（"系统知道何时不该测"） |
| `FPGA-Accelerated Vision Preprocessing` | 让评委在标题层面就知道 PL 不是转发器，自研 IP 有价值（对抗《01》4.2 提到的"FPGA 价值隐形"致命短板） |
| "知倦" | 二字、可读、有画面感，天然贴合疲劳主题；不含夸大医疗承诺 |

### 1.3 必须避免的措辞（统一口径，全组一致）

- ❌ 医疗诊断 / 疾病识别 / 健康评分 / 血氧 / 血压 / 医疗级精度
- ✅ 疲劳风险提示 / 状态趋势监测 / 非接触测量原型 / 受控条件下的心率呼吸趋势估计

## 三、项目简介（按字数选用，全部为可直接粘贴版本）

### 3.1 一句话版（≤ 25 字，登记表 / 展板标题）

> **用一颗摄像头看疲劳，用 FPGA 保证它测得准、报得及时。**

### 3.2 短版（约 60 字，PPT 副标题 / 视频片头）

> **知倦（VigiLens）是一套无接触疲劳监测终端：摄像头采集面部与上半身信息，先判断信号是否可信，再融合眨眼、闭眼比例、打哈欠、头部姿态给出可解释的疲劳风险提示；FPGA 承担确定性视觉与时序预处理。**

### 3.3 标准版（约 150 字，README 开头 / 报名表简介栏）

> **知倦（VigiLens）是一套基于摄像头与 FPGA 的无接触疲劳与生命体征趋势监测终端，面向长时间学习、值守等场景。系统只用一个普通 RGB 摄像头，提取眨眼频率、闭眼时长、PERCLOS、打哈欠、头部姿态与运动质量等指标，并在受控条件下给出心率/呼吸率趋势估计。与同类作品不同，本系统把"测量是否可信"作为核心能力：先由光照、运动、人脸可见率与波形稳定性做信号质量门控，不可靠时明确拒绝输出而非乱报数字。Mizar-Z7020 的 PL 端承担 ROI 统计、帧差运动量、FIR 滤波等确定性预处理，PS 端负责人脸关键点、指标计算与规则融合，网页端实时呈现指标、趋势曲线与可解释建议。**

### 3.4 详版（约 400 字，设计报告摘要 / 初赛说明）

> **知倦（VigiLens）** 是一套面向长时间学习与值守场景的**无接触疲劳与生命体征趋势监测终端**，参赛方向为 2026 全国大学生嵌入式芯片与系统设计竞赛 AMD 赛道 3.3 自主选题（初级组）。
>
> **问题**：长期学习或值守导致的疲劳难以自查，而现有疲劳监测方案要么需要接触式穿戴设备，要么只给出一个无法追溯的黑盒分数，甚至在信号明显不可靠时仍在输出数值。
>
> **方法**：系统仅使用一个普通 RGB 摄像头。PL（Mizar-Z7020）端完成 RGB/YUV 转换、缩放灰度化、ROI 像素统计、帧间运动量计算与 FIR 带通滤波，为上层提供低延迟、低抖动的确定性特征流；PS/后台端完成人脸与关键点检测，据此计算 EAR、MAR、PERCLOS、头部姿态与人脸可见率，融合光照、运动、遮挡与波形周期稳定性形成**信号质量评分**；在质量门控通过时，进一步给出心率/呼吸率趋势估计与置信度。
>
> **特色一：可信优先。** 系统主动回答"当前测量是否可信"，不确定时输出"信号不可靠/请调整姿势"，而非报出跳变数值——这是非接触测量真实落地的痛点所在。
> **特色二：硬件可量化。** 自研 `roi_statistic`、`motion_quality`、`fir_filter` 等 HLS IP，提供纯软件与 FPGA 模式在延迟、CPU 占用、吞吐与资源（LUT/FF/BRAM/DSP/WNS）上的同条件对比数据。
> **特色三：可解释。** 每一条建议都能追溯到触发它的指标与置信度，配合时间趋势曲线与事件日志，输出"正常 / 疲劳风险升高 / 请调整姿势 / 信号不可靠 / 连接中断 / 测量完成"六态结果。
>
> **边界声明**：本作品为实验室条件下的工程原型与健康趋势监测设备，**不用于医疗诊断**，不提供血氧、血压等 RGB 摄像头原理上不可靠的指标。

### 3.5 答辩开场 30 秒口播（背下来）

> "评委老师好，我们的作品叫**知倦**，英文名 **VigiLens**——Vigilance 加 Lens。
> 它只用一个普通摄像头，就能监测一个人的疲劳状态。但我们想强调的不是'能测出什么'，而是**'它知道自己什么时候不该测'**：当光照、运动或遮挡导致信号不可靠时，它会明确显示'信号不可靠'，而不是随便报一个数字。
> 这个判断需要在每一帧上做确定性的实时计算，所以我们把 ROI 统计、运动量和滤波放在 Mizar-Z7020 的 FPGA 里跑。这里是同一段输入下，软件模式和 FPGA 模式的延迟对比。"

## 四、英文版（决赛一页 A4 海报必需，直接可用）

### 4.1 One-liner

> **VigiLens — a trust-aware contactless fatigue monitor: one RGB camera, FPGA-accelerated vision preprocessing, and it tells you when its own measurement cannot be trusted.**

### 4.2 Abstract（约 120 words）

> VigiLens is a contactless fatigue and vital-trend monitoring terminal built on a Mizar-Z7020 (Zynq-7000) platform, targeting long study and duty-watch scenarios. From a single RGB camera it extracts blink rate, eye-closure duration, PERCLOS, yawning, head pose and motion quality, and — under controlled conditions — estimates heart and respiration rate trends. Its distinguishing capability is **trust-awareness**: light conditions, motion, face visibility and waveform stability are fused into a signal-quality gate that explicitly refuses to report a value when the measurement is unreliable. The PL fabric performs deterministic ROI statistics, inter-frame motion and FIR filtering for low-latency, low-jitter feature extraction; the PS runs landmark-based metrics, rule fusion and a WebSocket dashboard. Reproducible software-vs-FPGA latency, CPU and resource comparisons are provided. Not a medical device.

### 4.3 Keywords

`contactless monitoring` · `fatigue risk` · `signal-quality gating` · `rPPG trend` · `Mizar-Z7020` · `Vitis HLS` · `AXI-Stream / DMA` · `explainable decision` · `reproducibility`
