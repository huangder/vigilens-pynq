## 1. 为什么要做"年龄分层"

不是因为"分得越细越像在做研究"，而是因为**公开研究已经证明：同一个眼动阈值对不同年龄的人不成立**。

> **Cai et al. 2021**，*Sci Rep* 11:21561，DOI `10.1038/s41598-021-99133-y`（CC BY，本仓库已读全文）：
> 29 h 完全睡眠剥夺 + 实车闭环赛道，年轻组 16 人（24.26±3.15 岁）vs 老年组 17 人（57.31±5.17 岁）。
> 原文结论：**"Ocular measures of drowsiness, including blink duration, number of long eye closures and
> PERCLOS increased following sleep loss for younger adults only (p < 0.05)."**
> Table 3 实测：PERCLOS 年轻组 3.17% → 5.48%（p=0.003），老年组 3.51% → 3.85%（**不显著**，p=0.437）；
> 长闭眼率年轻组 4.43 → 14.63 /15min（p=0.007），老年组 5.05 → 7.20（不显著）。
> 而老年组的**驾驶损害照样出现**（车道偏离 3.5×，p=0.008），作者认为其损害可能来自 inattention/distraction。
>
> 独立佐证：**Abe 2023**，*Sleep Advances* 4(1):zpad006（CC BY）把 "in older adults" 明确列为
> PERCLOS **不**随困倦改变的情形之一。

**⇒ 结论（这条决定了整个模型架构）**：对老年用户套用统一的 PERCLOS 阈值会**系统性漏报**，
而漏报在安全方向上是比误报更坏的错误。因此本功能不是"给每个年龄段配一套阈值"那么浅，
而是**按年龄调整证据权重**（见 §5），并对老年组**提高非眼部证据（打哈欠 / 姿态漂移）的地位**。

**同时必须说清"分不了什么"**：文献**不支持**按年龄分**眨眼率** ——
Bentivoglio 1997（*Mov Disord* 12(6):1028-1034，n=150，5~87 岁）原文 **"No age-related differences were found."**；
Sun 1997（*IOVS* 38(1):92-99）同样报告 blink rate 无年龄变化（但幅度/峰值速度随年龄下降）。
而且**场景与性别的影响比年龄大**：Doughty 2001（*Optom Vis Sci* 78(10):712-725，题录与摘要原文已核）
给的是 reading 1.4~14.4 / primary gaze 8.0~21.0 / conversation 10.5~32.5 blinks/min（**差 5.8 倍**），
并明确写 "It is inappropriate to simply state a value for spontaneous eyeblink rate"。
⇒ 本项目把眨眼率作为**全局基线 + 场景口径**（`config.yaml: age_scenario: reading`，对应"桌面专注"场景），
**不按年龄分组**。顺带登记一处**未解决的文献冲突**（照 `AGENTS.md` §3 如实上报、不自行拍板）：
Sforza 2008（*Ophthalmic Physiol Opt* 28(4):345-353）报告老年女性比年轻女性眨眼更频繁，与前两条不一致。

## 2. 一个必须写下来的**否定结论**：现成的"年龄分层疲劳基线"不存在

> 本次检索**没有找到任何"既带困倦/疲劳标注、又带受试者年龄"的公开数据集**。

| 数据集 | 有年龄标注吗 | 核实到什么程度 |
|---|---|---|
| MRL Eye | **没有** | 官方页逐条列出 8 个标注项（含 gender、眼镜、光照、传感器…），**无 age**；84,898 张 / 37 人 |
| CEW（NUAA） | **没有** | 2,423 张（1,192 闭眼 + 1,231 睁眼，取自 LFW）；许可禁止转发下载链接 |
| DMD（Vicomtech） | 未核实 | 许可 **CC BY-NC-ND 4.0**、仅学术、18+（ND + NC 双限制要进合规风险表） |
| NTHU-DDD / UTA-RLDD / DROZY / ZJU / YawDD | 本次**未核实** | 检索配额中途耗尽（HTTP 429）——**不得**引用其年龄标注情况 |

**⇒ 因此"年龄分层疲劳参考数据库"只能自建。** 本次交付的是**能落地的部分**：
① 覆盖全部测量字段的库结构（§3）；② **经得起复核的少量基线** + 写清缺口的其余条目（§4）；
③ 采集协议（**素材与缺口见 §9 第 3/4 条**，尚未成文），让"自建"有明确的第一步。

**这也是本方案最重要的工程判断**：与其编一套好看的"各年龄段正常值"，不如如实交付
"只有一条基线可用、其余留空并写明为什么"。后者可以被复核，前者一旦被评审追问出处就会全线崩塌。

## 3. 数据库：结构覆盖全部测量字段，纪律保证不被污染

产物：`backend/fatigue_db.py`（标准库 `sqlite3`，**零新依赖**）+ `data/fatigue_db/schema.sql`（入库，供评审查结构）。
库本体 `data/fatigue_db/*.sqlite3` 在 `.gitignore` 里（含个体数据，不入库）。

| 表 | 装什么 | 关键纪律 |
|---|---|---|
| `sessions` | 一次会话：起止、帧数、**档案**（subject / age_years / age_band / age_source / confirmed_by / engine）、`provenance`、汇总统计 | `provenance` **由 `landmark_source` 判定**（`mediapipe`→`live`，`stub`→`stub`），**不靠调用方自觉** |
| `frames` | **逐帧全部测量字段**：EAR 左右 / 眨眼状态 / 眨眼计数 / 眨眼率 / PERCLOS / 长闭眼 / MAR / 哈欠 / 姿态 yaw-pitch-roll / 人脸可见率 / bbox / 心率与呼吸（含置信度）/ 光照-运动-总分质量 / status / advice / reason | 与 `backend/storage.py::CSV_COLUMNS` 同一套语义（那是导出表，这是查询库） |
| `comparisons` | 逐帧比对：`band_applied` / `comparable` / `risk` / `risk_level` / `deviation` / `contributions`(JSON) / `interactions`(JSON) / `reason` / 基线版本与出处 | **不可比的帧也写** —— "当时测不了"本身是要留档的事实 |
| `age_events` | 审计轨迹：观察开始/重启、收录决定、推断提议、忽略、人工确认、接受推断、重置、锁定后仍被调推断 | 记录功能；`kind` 枚举在 `age_infer.EVENT_KINDS` |
| `subjects` | 已收录主体：匿名 id、首末次出现、年龄与来源、**人脸签名（BLOB，256 字节）** | 存**签名不是照片** |
| `reference_norms` | 参照基线（带 `source` / `confidence` / `checked_on`） | 让查询自带出处，可审计 |

**"stub 会话不进人群统计"是硬约束**（`summary(include_stub=False)` 为默认）：
占位关键点的 EAR/MAR 是没有算法意义的几何量（`AGENTS.md` §9），一旦混进人群分布，
整张表就不可信了，而且事后无从分辨。测试 `test_stub_sessions_stay_out_of_population_stats` 钉住它。

## 4. 参照基线：`data/reference/age_bands.json`

**结构上刻意分成两段**，这是防"隐形错误"的关键设计：

- `bands.<组>.<指标>` —— **唯一的基线来源**。只有同时给出 `typical` 与尺度（或给出 `low`/`high`）才算"可用"；
  模型只会用这里的数字。
- `evidence.<主题>` —— **证据，不是基线**。放"别的场景、别的测量口径下测到的数字"（如 Cai 2021 的实车 PERCLOS），
  用来解释"为什么这样定权重"。**代码不许拿它当基线** —— 一旦混进去，就会把驾驶场景的 PERCLOS
  当成桌面场景的正常值，而这是最隐蔽的一类错误。`check_age_sidecar.py` 的 T3.6 专门检查两者分开。

本次实际放进 `bands` 的数值基线**只有一条**：

| 组 | 指标 | 值 | 出处 | 置信度 |
|---|---|---|---|---|
| `global` | `blink_rate_per_min` | 1.4~14.4（reading 场景，典型取中点 7.9） | Doughty 2001（题录已核） | 【已验证】 |

其余条目（PERCLOS / 长闭眼 / 哈欠）**一律留空并写明缺口**，代码在找不到可用基线时：
① 退化到 `config.yaml` 的阈值，并在结果里标注 **"⚠️ 占位值，未标定"**；
② 或直接跳过该指标并在 `reason` 里写"无可用基线"。**两者都不许编数字。**

> ⚠️ **口径差异必须一起说**：Dinges & Grace 1998（FHWA-MCRT-98-006，ROSA P 官方页已读）描述 PERCLOS 时
> 强调它反映 **slow eyelid closures（droops）而不是 blinks**；而本项目 `behavior_metrics.py` 的 PERCLOS 是
> "EAR 低于阈值的时间占比"，**包含快速眨眼**。两者不等价。是否排除快速眨眼是一个**显式的设计决定**，
> 当前实现**未排除**（列入 §9 未验证清单）。另外常被引用的 0.15/0.25/0.40 三级阈值
> **追不到一手出处**（只有二手转述），因此 `config.yaml` 的 `perclos_warning: 0.25` 仍标"占位值"，
> **不得**在任何报告里写成"国际标准阈值"。

## 5. 耦合判定模型：`backend/fatigue_coupling.py`

### 5.1 为什么不用"阈值 OR"

既有 `decision.py` 的六态判定是**规则融合**（任一指标越线即告警），它可解释、够用，但
① **证据强度不可加**（刚越线 与 大幅越线 + 长闭眼 + 哈欠，是同一个结论）；
② **年龄不改权重**，而 §1 已证明这正是必须改的地方。

### 5.2 模型（对数几率形式的证据累积，可解释、可加、可门控）

```
logOdds_t = prior + Σ_i  sens_i(band) · w_quality · clip(gain_i · z_i)  +  耦合项
S_t       = (1-α)·S_{t-1} + α·logOdds_t          # 时序累积（指数记忆）
risk      = sigmoid(S_t)                          # 0~1 → 档位 low/medium/high
```

| 符号 | 含义 | 值从哪来 |
|---|---|---|
| `z_i` | 指标相对**同龄基线**的标准化偏离 `(value − typical) / scale` | `age_bands.json`；无可用基线 → 跳过并说明 |
| `gain_i` | 各指标的证据增益 | `config.yaml: couple_gain_*`　**⚠️ 全部未标定（占位值）** |
| `sens_i(band)` | **年龄敏感度**：60+ 组眼部证据下调、非眼部上调 | `couple_eye_sensitivity_older` 等（方向有文献依据，数值是占位值） |
| `w_quality` | 质量收缩：质量越差证据越弱（不是"照样报警"） | 由 `quality.overall` 与 `face.visible` 算出 |
| 耦合项 | **显式指标交互**：高 PERCLOS × 长闭眼；高 PERCLOS × 眨眼率被抑制 | `couple_interaction_*` |
| `α` | 记忆系数 | `couple_memory_alpha` |

**三条硬纪律（写在代码里，也由测试钉住）**：

1. **先判断能不能测**：`status ∉ {normal, fatigue_risk}`、或质量门控不过、或人脸可见率不足
   → 输出 `comparable=false` + `risk=null` + `risk_level="unknown"`。**不报跳变数字**是本产品的承诺，
   与 `vital.*` 为 null 同一口径。
2. **每个数字都要能说出处**：每条证据带 `baseline`（出处说明）与 `confidence`；比对结果带
   `reference_version` 与 `reference_sources`。
3. **不许编数字**：`config.yaml` 里标 `⚠️ 占位值` 的常量一律未标定，输出只能说"风险档位"。

### 5.3 本机实测到的行为（真实运行，非推演）

| 输入 | 参照组 | 结果 |
|---|---|---|
| 平静（PERCLOS 0.06 / 眨眼率 18） | adult | `risk=0.04` → **low** |
| 疲劳（PERCLOS 0.34 / 长闭眼 2 / 哈欠 3 / 眨眼率 6） | adult | `risk=0.98` → **high**，触发 `perclos_x_longclose` |
| 同上（只给眼部证据） | young_adult vs **older_adult** | `0.8793` vs **`0.6824`** —— 老年组眼部证据被下调（§1 的方向） |
| 质量 0.42 / status=unreliable | 任意 | `comparable=false`，`risk=null`，`risk_level=unknown` |

最后一行尤其重要：真实视频 `data/raw/blink.mp4` 跑 656 帧时，**11 帧可比、645 帧 unknown**，
而那 11 帧**恰好等于** `normal`(4) + `fatigue_risk`(7) —— 拒绝对不可用帧报数字的规则**逐帧成立**。

## 6. PS 端：年龄推测、收录窗口、一次性确认后停用

### 6.1 年龄推断引擎（可插拔，`backend/age_infer.py`）

| 引擎 | 是什么 | `placeholder` | 何时被选中 |
|---|---|---|---|
| `opencv_caffe` | OpenCV DNN + **Levi & Hassner (2015)** 8 档年龄分类模型（`deploy_age.prototxt` + `age_net.caffemodel`，输入 227×227，均值 (78.426, 87.769, 114.896)） | `false` | `age_engine_order` 里排第一且**权重存在**时 |
| `heuristic` | 零依赖占位：面部纹理能量 + 人脸框纵横比 → 宽区间低置信 | **`true`** | 缺权重时的兜底（保证链路可测） |
| `none` | 没有可用引擎 | — | 全不可用 → `estimate.engine="none"`，前端显示"本次未做推断" |

三条诚实性约束：**① 推断只是建议**，未经用户确认**不得**用于选择参照组（schema 层禁止
`source=image_estimate` 且 `confirmed=true` 而不带 `confirmed_by=user_accepted_estimate`）；
**② 占位引擎必须自我标注**，置信度被硬压在 `PLACEHOLDER_CONFIDENCE_CAP=0.25` 以下；
**③ 精度一个数字都不许写** —— 本项目没有在本机/本场景测过年龄误差，报告里若引用精度，
必须同时给出基准数据集 + 输入分辨率 + 指标定义（正例：Jamo 2025 在 IMDB-Clean 1000 张、224×224 下
MAE 10.83 岁(DeepFace) / 7.46 岁(InsightFace)；**反例**：只写"±4.65 岁"而不给数据集）。

### 6.2 "给予年龄识别机制一个判断是否收录人脸的时间"

这是用户明确要求的行为，落地为一个**可配置的观察窗口**（`age_enroll_window_s` 默认 20 s）：

```
有脸 + 质量≥阈值 ──► observing（累计有效样本 / 累计时长 / 进度）
   连续 N 帧"不像同一个人" ──► 重启观察（记 enroll_observe_restart）
   窗口到期 ──► 有效样本 ≥ age_enroll_min_samples ? enrolled : rejected
   用户直接表态 ──► enroll_decision(accept) 立即判定
```

- **无效帧不计样本也不推进窗口**（质量或可见率不足时明确写在 `reason` 里）；
- 收录用窗口内**样本的中位数签名**，比第一帧稳（抗姿态抖动）；
- 判定为"不收录"**不是错误**，是如实结论；用户也可以直接选择不收录。

### 6.3 "一次正式确认年龄后不再采用年龄推测机制"

```
profile.confirmed=true 且 locked=true（age_confirm_locks_inference）
   ⇒ inference_allowed() 恒为 false（管线**先问再调**）
   ⇒ 若第三方调用方不问就调 maybe_infer()，会把 inference_calls_after_lock +1，
      而 age_contract 的校验器**当场报错** → 违规留痕，而不是静默发生
```

本机实测：`--age-confirm 31` 之后 `locked=True`、`inference_allowed()=False`、
`inference_calls_after_lock=0`，档案件校验通过；而故意在锁定后再调一次推断，
schema 立刻给出 `年龄已确认并锁定，但 inference_calls_after_lock > 0（违反「确认后停用年龄推测」的承诺）`。
**这条规则真的抓到过一次实现缺陷**：管线首版没先问就调，`--age-confirm` 一开就整段红着结束。

### 6.4 隐私：签名不是照片

`FaceSignature`：bbox 裁剪 → 灰度 → 16×16 降采样 → 去均值/归一化 → int8 量化 = **256 字节**。
用途只有"这次的脸和上次是不是同一个人"（距离阈值判同人，匿名 id = `sha1(签名)[:12]`）。
它**不保存可辨识的人脸图像**（对比：契约帧原图 640×480×3 = 921600 字节），
但仍属**由人脸派生的个人信息** → 默认只留本地、不外传（`age_stores_face_image=false`），
`privacy` 段如实声明 `signature_kind`。退化输入（框太小、纯色无区分度）**返回 None**，
否则所有"平脸"会长得一样、制造出假的"同一个人"。

## 7. 三线路实现路径

### 7.1 A 线路（算法/后端，纯软件路径）—— ✅ 已落地

| 项 | 内容 |
|---|---|
| 目标 | 不依赖板卡与相机，在 PC 上跑通"推断 → 收录 → 比对 → 落库 → 出档案件" |
