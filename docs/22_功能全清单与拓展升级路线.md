## 3. 拓展升级方案（提案集）

### 3.0 立项五条兼容性红线（**任何一条违反，方案直接作废**）

1. **契约帧一个字节不动**：A→B 永远只有那 9 个字段、`status` 永远 6 值。新能力一律走**旁路**（`/api/status`、`/api/preview`、独立 REST/WS 资源）。
2. **阈值只进 `config.yaml`**：代码里不出现魔法数字；新增阈值必须写依据与出处。
3. **碰 IP 就走全套**：新 IP / 改口径 = 先改 `docs/interface.md` → 两套实现 → 新黄金参考（**容差 0**）→ csim + csynth + cosim → 公告会签。
4. **"能不能测"优先于"测出什么"**：任何新指标都必须能被质量门控拦住，且拦不住时要**明确输出"不可靠"而不是给数字**。
5. **不改写历史**：升级不修改既有黄金参考或断言去"凑绿"；旧结论保持可复现。

**评分口径**（每条方案按这五项打分，避免"看着酷但做不完"）：

| 维度 | 问法 |
|---|---|
| 演示性 | 现场 60~90 秒内，**肉眼能看到什么变化**？断网/无板卡时能不能退化成 Mock？ |
| 创新性 | 是"别人也这么做"，还是"我们有自己的口径/证据"？有没有**可写进报告的对照实验**？ |
| 实用性 | 离开赛场还有没有人用？能不能解决现有欠账（占位阈值、rPPG 出数、证据链）？ |
| 成本 | 人日 + 是否**需要板卡/相机**（M3 前的项必须能离线做） |
| 风险 | 触不触隐私/医疗红线？会不会让既有回归变红？ |

### 桶 A：把"先判断能不能测"从口号变成**可测量的科学**（全部**不动契约**，M3 前就能做）

> 这是本项目最大的差异化卖点，也是目前**唯一还没有对照实验撑住**的地方。性价比最高。

#### A-1 质量门控压力测试台（Quality-Gate Stress Bench）

- **做什么**：写一个脚本，把同一段真实视频按**受控方式退化**（亮度 ±、加入运动/抖动、局部遮挡、降帧率、加噪），
  对每个退化档跑完整管线，记录 `quality.*` 与指标输出，画两条曲线：
  ① `quality.overall` vs 退化量；② **指标误差 / 是否拒答** vs `quality.overall`。
- **演示性**：★★★★★ 一张图说清"我们不是测得更准，而是**知道什么时候不该测**"。
- **创新性**：★★★★ 把"门控"从主观描述变成**可复现的误差-质量曲线**（含"拒答率"这一项）。
- **实用性**：★★★★★ 直接产出答辩与报告的核心图；顺带给阈值标定提供依据。
- **兼容性**：只加 `metrics/scripts/` 脚本 + `docs/` 说明；**不改契约、不改管线**。
- **成本**：2~3 人日（需要一段真实视频，`data/raw/` 现在为空）。
- **风险**：退化必须**合成得可解释**（记录每个档怎么做的），否则数字会被质疑。
- **验收**：脚本一条命令跑完，输出 CSV + 图 + 每个档的 `landmark_source`、`status`、`vital.*` 是否为 `null`。

#### A-2 置信度与不确定性输出（SQI + 谱峰显著性 + 置信区间）

- **做什么**：把 `hr_conf` 从"有/无"变成**可解释的数字**：谱峰显著性（峰/邻域能量比）、
  有效样本数、ROI 稳定性、信号质量指数（SQI）合成；进一步给 **BPM 置信区间**。
- **演示性**：★★★★ 网页上心率显示成"72 ± 3 BPM（置信度 0.82）"，而不是裸数字；门控不通过时整块变灰。
- **创新性**：★★★★ 绝大多数学生作品只报一个数；**报不确定度**才是"测量系统"而非"玩具"。
- **实用性**：★★★★★ 直接提升 A10 的可信度，且**天然接上 A-1 的误差曲线**。
- **兼容性**：`vital.hr_conf` 字段**已存在**（契约 §7.4），只是先填得更"有信息"；SQI 细节走旁路 `triggers`/`/api/status`。
- **成本**：3~4 人日（算法在 PS 侧，纯软件）。
- **风险**：**不得**把置信度包装成"准确率"；措辞只能是"趋势估计 + 置信度"（铁律 5）。
- **验收**：`pytest` 新增用例（合成信号注入已知频率 → 置信度随 SNR 单调变化）。

#### A-3 逐字节确定性审计 + 证据清单（Replay Audit & Evidence Manifest）

- **做什么**：一次运行产出 `run_id` + 输入哈希（视频帧序列哈希）+ 输出哈希（末帧 JSON / CSV / 旁路帧数），
  写一份 `manifest.json`；提供 `--verify <manifest>` 一键复算并比对。
- **演示性**：★★★★ "同一段回放跑两次，哈希相同"现场可验（评审最爱）。
- **创新性**：★★★ 把 `AGENTS.md` 的确定性纪律**工程化**为可执行证据。
- **实用性**：★★★★★ 报告/答辩的"可复现"从承诺变成命令与产物；也防"改代码后旧结论失效"。
- **兼容性**：只加脚本与产物格式（`metrics/evidence/`）；契约不动。
- **成本**：1~2 人日。
- **风险**：注意 `.gitignore` 边界 —— `metrics/evidence/` **必须入库**、`metrics/logs/` 不入库。

#### A-4 阈值标定工作流 + 个体基线自校准

- **做什么**：① 把 A17 的占位阈值（EAR/MAR/头姿/光照/运动/权重）用**真实标注素材**标定出第一版，
  每个值写依据与复现命令；② 增加"前 60 秒个人基线"逻辑（闭眼 EAR 相对自身基线下降比例），
  让"阈值因人而异"变成产品能力。
- **演示性**：★★★★ "换一个人坐上来，30 秒后系统自己找到他的基线"。
- **创新性**：★★★★ 个体基线是成熟思路，但在**学生作品里少见**；且正好回应"占位阈值"这条最大欠账。
- **实用性**：★★★★★ 不标定，`fatigue_risk` 就是假的；这条决定产品能不能用。
- **兼容性**：新增阈值进 `config.yaml`（共享文件，改前说一声）；契约字段不动。
- **成本**：5~8 人日（**最大成本是录 4 段标准视频并人工标注**，`DAT-001`/`DAT-002`）。
- **风险**：隐私红线 —— 视频不入库、不出镜者同意；标注产物只存统计量。

### 桶 B：算法与指标能力（A 线为主，契约**已经留好位置**）

#### B-1 rPPG 端到端打通 + 多算法对照（GREEN / CHROM / POS / PBV）

- **做什么**：在**已有链路**（Q1.15 → FIR → 谱峰）上，补齐真实视频端到端出数：
  先修时间基准（BUG-029：链路实测帧率 ≠ 30 Hz）与窗口/录制时长冲突（BUG-012），
  再把 ROI 从"额头固定框"（BUG-011：`forehead_roi` 取到的其实是眼睛）改成**避开眼嘴的稳定皮肤区**，
  并做**多算法对照**（GREEN 为基线，CHROM / POS / PBV 至少上一种）。
- **演示性**：★★★★★ 网页上实时心率曲线 + 与参考设备（手指 PPG / 商用手表）的对照。
- **创新性**：★★★★ **不是"抄一个算法"，而是"同一串输入样本、多种算法、逐项对拍"** —— 与既有黄金参考体系同构。
- **实用性**：★★★★★ 心率是产品承诺的一部分；目前"大面积为 `null`"虽有正当理由，但**长期无输出等于没做**。
- **兼容性**：`vital.*` 四个键**已冻结且允许 `null`**，填进去不需要改契约；质量门控照旧。
- **成本**：5~10 人日（真实视频 + 参考测量是瓶颈）。
- **风险**：**绝不承诺医疗精度**；报告必须写"受控条件 + 趋势 + 置信度"。
- **验收**：同一段视频，`landmark_source=mediapipe` 且 `quality.overall ≥ vital_require_quality` 时
  `vital.hr_bpm` 非 `null`；与参考设备做 Bland-Altman 式对照（**只报实测差值，不报宣称精度**）。

#### B-2 呼吸率趋势（走契约 §3.5 **已经写好的路**）

- **做什么**：契约已明确"呼吸带（0.1~0.5 Hz）必须由 **PS 侧先降采样**（如降到 2 Hz）再用同名 FIR IP 的第二组系数"。
  把这步实现：胸/肩 ROI → 亮度或位移序列 → 降采样 → 第二组系数带通 → 周期检测 → `rr_per_min`。
- **演示性**：★★★★ 与心率同屏，两条趋势线一起动。
- **创新性**：★★★ 属于"契约已给口径但没人做"的**确定性推进**，风险低。
- **实用性**：★★★★ 补齐 `vital` 的两个空键。
- **兼容性**：**契约 §3.5 已给出口径**；需要一组新系数（`design_fir_coeffs.py` 已有工具）+ 新黄金参考。
- **成本**：3~5 人日。
- **风险**：`rr_conf` 必须诚实（人脸可见时呼吸可靠性下降）；不得因为"想看到数字"而放宽门控。

#### B-3 60 fps 带来的时间分辨率红利 + 微睡眠（microsleep）事件

- **做什么**：CM2/720p60 链路上线后，`min_close_frames: 3` 对应的最短可检出闭眼从 100 ms（30 fps）降到 **50 ms**；
  增加 `microsleep` 事件（≥ 0.5~1 s 的闭眼，事件级输出，含起止时间与质量）。
- **演示性**：★★★★★ 现场演示"低头 0.8 秒"被抓到并在时间轴标红。
- **创新性**：★★★★ 把"帧率"从参数变成**能力量化**（O6 已给出公式 `最短可检出闭眼 = 3 / fps`）。
- **实用性**：★★★★ 微睡眠是疲劳监测里最有价值的事件之一。
- **兼容性**：事件走**旁路**（`triggers`/事件日志）；`behavior.*` 字段不变（如需新增键 → 走契约流程）。
- **成本**：2~3 人日（依赖 60 fps 链路，可先在 30 fps 上把逻辑写完）。
- **风险**：必须先有 60 fps 真实帧源；否则只能写"逻辑已就绪、待高帧率源验证"。

#### B-4 多模态旁路融合（环境光 + 键鼠空闲 + 可选温湿度）

- **做什么**：把 `light_score` 与一个**真实环境光传感器**读数对齐（校准曲线），
  并把"键盘鼠标空闲时长"作为旁路特征（说明人是否真的在学习、是否已离开）。
- **演示性**：★★★★ "关灯 → 光照分下降 → 系统主动提示不可靠"现场复现。
- **创新性**：★★★★ 多传感器融合 + **交叉校验**（摄像头说暗、传感器也说暗 = 可信）。
- **实用性**：★★★★★ 键盘空闲能有效区分"闭眼休息"与"人已经走了"。
- **兼容性**：全部走旁路；不新增契约字段。
- **成本**：2~4 人日（传感器几元级；Linux 侧读 `/dev` 或串口）。
- **风险**：不得把"离开"判定成"疲劳"；也不得把键鼠数据上传。

### 桶 C：PL / 硬件侧升级（C 线为主，**最贴赛题**）

#### C-1 光照质量评分下沉到 PL（`sum_gray` 已经在算）

- **做什么**：`rgb2gray` 已经在输出 `sum_gray`（`docs/20` §3.3 已指出），
  把光照均值/饱和比例做成 **PL 侧输出寄存器** + PS 侧只读，省掉 PS 的全图遍历。
- **演示性**：★★★★ 软硬件耗时对比条（"同一件事，PS 3.6 ms，PL 几微秒"）。
- **创新性**：★★★★★ **把"质量门控"这一核心卖点的一部分做进 PL** —— 直接回应"FPGA 不是转发器"。
- **实用性**：★★★★ 降低 PS 负载，A9 上尤其有意义。
- **兼容性**：**要动契约 §3.4**（新增输出寄存器）→ 走完整契约流程 + 新黄金参考 + csim/csynth/cosim。
- **成本**：3~5 人日（含 HLS 重综合）。
- **风险**：口径必须与 A 线 `quality.light_score` 完全一致，否则软硬件对比立刻不一致。

#### C-2 软 ROI 平移（**用 `crop_x0` 跟随人脸**，替代云台）

- **做什么**：`frame_scale` 的参数里有 `crop_x0`（`docs/20` §2.2 已写明"将来做跟随人脸的 ROI 平移时直接移动它"）。
  用 PS 侧人脸框反馈，**逐帧平移裁剪窗口**让人脸保持在画面中心，而不是去转动相机。
- **演示性**：★★★★★ 人左右移动，画面窗口跟着走，**测量不中断**。
- **创新性**：★★★★★ 这是对 `docs/10` §5.3 那个"**云台一动、测量就废**"架构冲突的**纯软件解法**：
  平移裁剪窗口不引入帧间像素差（整帧仍在同一时刻曝光），运动分不会飙升。
- **实用性**：★★★★★ 云台已搁置，这条等于把云台的功能用 0 硬件成本拿回来。
- **兼容性**：新参数走 `config.yaml`；是否新增寄存器（`crop_x0` 已是 IP 输入）需按现有接口确认；黄金参考需覆盖不同 `crop_x0`。
- **成本**：3~5 人日。
- **风险**：**必须先有真实帧源**（MIPI 链路或降规格采集）；平移本身会造成画面内容变化，运动分是否仍稳需实测（【推测】不会飙升，理由是曝光同一时刻）。

#### C-3 全局运动估计 / 抖动补偿 IP（投影互相关或相位相关）

- **做什么**：在 PL 里用**行/列投影互相关**（或小窗口相位相关）估计相邻帧的全局位移，
  输出 `dx, dy` 与置信度；给质量门控一个"这是相机在动还是人在动"的判据。
- **演示性**：★★★★ 晃动相机 → 网页明确显示"检测到全局运动，测量暂停"，而不是报一堆错数。
- **创新性**：★★★★★ 把"运动伪影"从**一个标量**升级为**可分解的成因**（全局 vs 局部）。
- **实用性**：★★★★ 直接服务 A-1 的误差曲线与 B-1 的 rPPG 鲁棒性。
- **兼容性**：新 IP → 契约 §3 新增条目 + 黄金参考（整数互相关可做到容差 0）+ csim/csynth/cosim。
- **成本**：5~8 人日（HLS 难度中等，注意行缓冲的 BRAM 台阶规则）。
- **风险**：BRAM 预算（[2 的幂台阶] 规律）必须先算再写；可先用 384×288 灰度做，成本最低。

#### C-4 PL 侧"确定性"的量化：帧抖动直方图 + 延迟预算实测

- **做什么**：在 PL 里加一个**免费计时器 + 抖动计数器**（或上板用 ILA），
  实测 per-frame 间隔抖动、PL 处理延迟，输出直方图；与 PS 侧软件滤波的抖动做对比。
- **演示性**：★★★★★ 一张"抖动对比图"：软件（毫秒级抖动、受调度影响）vs PL（微秒级、确定性）。
- **创新性**：★★★★★ 项目一直宣称"低延迟、低抖动"（README 原话），**但从来没有量化过** —— 这条把它变成数据。
- **实用性**：★★★★ M4 的软硬件对比表直接需要它。
- **兼容性**：计数器可以做成 IP 输出寄存器（走契约流程），也可以先在 board 侧脚本里用 ILA 抓（**完全不动契约**）。
- **成本**：2~4 人日（**需要板卡**）。
- **风险**：前提是 Mizar 上电；拿不到板卡就只能写方案，**不得编数字**。

#### C-5 把 7 个 IP 的验证钉进 CI（csim 也要在 CI 里有出口）

- **做什么**：GitHub Actions 跑 `pytest` + 全部 `check_*.py` + `host_model_*.exe`（主机模型可在 CI 跑）；
  csim 因需 Vitis 授权，改为**在完整权限终端跑完后把日志与哈希归档**并写进证据清单（A-3）。
- **演示性**：★★（对评审是加分，不是现场亮点）。
- **创新性**：★★★ 工程规范性。
- **实用性**：★★★★★ 防止"改一边没改另一边"（项目已有多次此类教训：BUG-032、DOC-005）。
- **成本**：1~2 人日。
- **风险**：CI 里**不许出现"跑不了就当通过"**；跑不了的项目必须显式列为 skipped 并说明。

#### C-6 MIPI CM2 链路落地（**已立项**，按 `docs/19`/`docs/20` 推进）

- **做什么**：① 三个新 IP 的 csim/csynth/cosim 与资源时序；② 60 Hz FIR 系数定稿（工作区已生成 N=127 的候选，**待对拍与 csim**）；
  ③ MIPI 差分对 XDC + PS7 DDR 参数 + BD + bitstream；④ 上电首测用 **IMX219 内置 test pattern** 核对 Bayer 相位（`docs/20` §4.3）。
- **演示性**：★★★★★ "PL 里真的在做 demosaic"——这是最硬核、也最能证明"不是转发器"的证据。
- **成本**：高（含板卡与人日），但**这是主线**，其余升级都建立在它之上。
- **风险**：见 `docs/19` §8 的 9 条（授权说法冲突、供电未量、beat 形式假设、DDR 参数不得猜、FPC 插反、排线勿加长）。

#### C-7 板驱显示屏（HDMI）：**脱 PC 独立演示模式**

- **演示性**：★★★★★ "终端自己带屏"是嵌入式赛道的天然亮点。
- **创新性**：★★★★ 需要新的视频输出通路（**契约需先开视频输出口径**，`docs/10` §10 第 5 条待拍板）。
- **实用性**：★★★★ 真实产品形态。
- **兼容性**：**新通路 = 新契约条目**；建议先按"旁路显示通道"设计，绝不触碰测量帧。

#### C-8 微型神经网络的 PL 探索（hls4ml 类）

- **做什么**：把"眨眼/闭眼"从**阈值状态机**升级为**小序列分类器**（例如 16 帧 EAR/MAR 特征 → 2 层 MLP），
  用 HLS 综合上 PL，与阈值法做**延迟/抖动/一致性**对照。
- **演示性**：★★★★★ "同一个眨眼，两种判定器同时跑，PL 版延迟更低"。
- **创新性**：★★★★★ 探索性最强的一条（**风险也最高**）。
- **实用性**：★★★ 精度未必赢阈值法，价值在"PL 上能不能跑得动"的证据。
- **兼容性**：作为**旁路对照器**接入，不改契约；只有对照结论进报告。
- **成本**：8~15 人日（模型训练 + HLS + 黄金参考）。
- **风险**：⚠️ **不要与 DPU/Vitis AI 混淆** —— Zynq-7000 **不在 Vitis AI 官方支持范围**（`docs/20` §3.4）。
