## 1. 这一轮查出来并修掉的四个真问题

| ID | 问题 | 结论 | 台账 |
|---|---|---|---|
| BUG-035 | `axi_dma` 被建成 **Scatter-Gather 模式**（`c_include_sg=1`），`MM2S_LENGTH` 不生效 | ✅ 已修（BD 关 SG + 删 cntrl/sts 未接的流） | `docs/16` |
| — | **DMA 寄存器写序错**：固件写成 `地址→LENGTH→RS` | ✅ 已修。PG021 明文：**`LENGTH` 必须最后写**（写 LENGTH 才是启动事件）。写错时通道"自认在跑"，**不发 AR、不发 TVALID、SR 无任何错误位** | 记录在 `.tmp/s4/bench/s4_bench.c` 注释 |
| BUG-036 | `c_sg_length_width=14` ⇒ 921600 被截成 `0x1000`；`conv_rgb` 是 **32→24 非整数收窄**（DMA 每拍 TKEEP 全 1，4 不是 3 的整数倍 ⇒ 永不成帧） | ✅ 已修（长度位宽 23；MM2S 流宽 8；`conv_rgb` 改 1→3） | `docs/16` |
| BUG-037 | S2MM 目标长度**正好等于一帧字节数**时，收满即 halt ⇒ 下游 TREADY 撤掉 ⇒ **ROI/rgb2gray 卡在帧末收尾**（`CTRL=0x1`、结果寄存器全 0），而灰度数据其实是对的 | ✅ 接法已定：**长度留 384 B 余量 + 帧末软件写 `S2MM_CR.RS=0`** | `docs/16` |

> 排查方法上的两条经验（值得复用）：
> 1. **"寄存器全绿 + 数据死寂 + 无总线错误位"** ⇒ 按 ① 地址映射 ② 长度/位宽参数 ③ 流宽比是否整数 依次查，第 ③ 条最阴（不报错、只是永不给 TREADY）。
> 2. **本地取证要分层缩小**：mini（1×1 帧）→ 只启 roi → 换不可达地址看 DECERR → 链尾留余量。每一步只改一个变量。

### 2.2 长跑（`long` = 300 帧）

```text
long_frames=300  long_ok_frames=300  long_fails=0  long_first_fail=0
long_roi_fid=301  long_rgb_fid=301  long_mot_fid=301     # 第 1 次（fid0=1）
long_roi_fid=302  long_rgb_fid=302  long_mot_fid=302     # 第 2 次（fid0=2，未重烧）

```

> 300 帧每帧都做了：**软复位两通道 → W1C 清 SR → 启动三个 IP → S2MM(RS→DA→LEN=帧+384) → MM2S(RS→SA→LEN=整帧) → 等 MM2S IOC → 等三个 ap_done → 软件停 S2MM → 校验三个 frame_id 逐帧 +1**。第 1 帧曾经失败（SR=0x5011），根因是"上一帧是手动停的、不复位直接续写 LEN"，加上每帧软复位后就好了。

## 5. 这一轮踩过的坑（省时间用）

| 坑 | 结论 |
|---|---|
| **ps7_init 跑到一半被打断** | PS 的 PLL/时钟停在半初始化 ⇒ SLCR 读 0、DDR 报 `controller is held in reset`、`rst -system` 报 `Timeout waiting for PLL lock` ⇒ **只能断电重上电** |
| **`ps7_init` 里 `mask_poll` 上限 1e8 次** | 一次读 ≈1 ms ⇒ 可能卡几小时。驱动里已覆盖成 2 万次上限，超时打 `POLLTIMEOUT` |
| **高频 `mrd` 轮询** | 会把 FTDI 拖掉线（`FT_Write failed: io error`）⇒ 轮询必须放进 CPU（裸机固件），JTAG 只下载 + 取结果块 |
| **PL 地址写** | 必须 `mwr -force`；`memmap` 对 PL 无效 |
| **DAP `0x30000021` / `0xF0000021`** | 是 AHB-AP 的 sticky error，不是板坏：`targets -set -filter {name =~ "*DAP*"}` → `rst -dap` 即可清（**必须用 `targets -set`，不是 `jtag targets -set`**） |
| **`Set-Content -Encoding utf8` 写 .tcl** | 会加 BOM ⇒ xsdb 报 `invalid command name "﻿connect"`；`.tcl` / 提交信息**一律无 BOM**（用 `write` 工具或 `[System.IO.File]::WriteAllText`） |
| **用 PowerShell 往返改写仓库里的 UTF-8 文件** | 会按 GBK 解码 + 加 BOM + 丢换行（本轮把 `build_bd.tcl` 写坏过一次，还连带 `git checkout --` 抹掉未提交成果）。**读用 read、改用 edit/write** |
| **`frame_id` 的归零条件** | **重烧 bitstream** 会清零；只重跑程序不清零（所以第二次 `long` 的 `fid0=2`） |
| **微测试没 arm S2MM** | 整链反压，4 B 也搬不动 ⇒ 那种"微传输失败"不能当判据（BUG-036 里已把该条作废） |
