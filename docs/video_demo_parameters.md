# VigiLens 视频演示参数与取证说明

记录日期：2026-11-03，时区 Asia/Shanghai。本文件记录技术参数和演示边界，不代替人工协作记录或人体准确性验收。

**最新开发档见 [全链路含心率60Hz记录](all60_development.md)**。下表是既有SD包参数；目前RAM中另行运行全60Hz开发包，心率不再使用中间30Hz汇聚方案。新档的实际性能需引用对应版本实测，不能沿用旧53.56fps成绩。

后续 60 fps 实验见 [完整检测链优化记录](full60_optimization.md)。实验短测最高 55.33 fps，使用相近正式滤波时间跨度的候选首轮 53.84 fps、后续复测有下降；**未实现稳定完整 60 fps，当前 SD 服务仍为下表的 30 fps 版本**。视频中应将请求模式、实际处理帧率和网页预览频率分别标注。

## 图像与计算链

【已验证：配置与实现】USB UVC 相机 → PS 采集/像素转换 → PL ROI 统计、灰度与运动量 → PS 人脸/ERT 关键点、行为、质量门控、rPPG → HTTP → PC 浏览器。

当前 `ert_temporal` 路线使用人脸检测与 68 点 ERT 模型。额头 RGB 统计、心率 FIR 与频谱计算在 PS 执行；独立 HLS `fir_filter`、`frame_scale` 源码的存在不代表已接入当前心率链。电脑浏览器负责展示，不需要启动 PC 算法后端。

| 项目 | 当前运行配置 | 视频中应如何表达 |
|---|---|---|
| 相机 | `/dev/video0`，640×480，YUYV | 当前演示分辨率是 640×480 |
| 标称采样率 | 30 Hz | 这是目标配置；完整负载实测帧率需单独引用日志 |
| 视觉运行时 | `ert_temporal` | 板端人脸与 ERT 关键点计算 |
| 预览编码/请求 | 5 Hz，JPEG 质量 80 | 显示旁路，与指标采样频率分开 |
| HTTP 指标轮询 | 5 Hz（200 ms） | 网页每秒取约 5 次最新指标，不等于分析只有 5 fps |
| 页面动画上限 | 30 Hz | 浏览器绘制节奏，不是有效测量帧率 |
| 行为/质量滑窗 | 30 s | PERCLOS、眨眼率及质量统计的窗口 |

配置中的 720p 档位、PC MediaPipe/年龄模块、呼吸率和录像辅助入口不能当作本轮板端实际功能展示。

## 眼部与疲劳提示参数

【已验证：当前候选配置】全部来自根 `config.yaml`。板端眼部候选和 PC 旧参考策略分别保留；候选未会签，JSON 契约版本未升级。

| 参数 | 板端当前值 | 含义 |
|---|---|---|
| EAR | 双眼 EAR 的均值 | `EAR=(上下两组眼睑距离之和)/(2×眼角间距)`；界面“400”对应 0.400 |
| 闭合阈值 | 均值严格小于 0.400 | 不是单帧低于阈值就立即累计一次 |
| 重新睁眼阈值 | 均值大于或等于 0.430 | 与闭合阈值构成迟滞，减少边缘波动重复计数 |
| 闭眼最短确认 | 80 ms | 排除更短低 EAR 波动 |
| 睁眼连续确认 | 100 ms | 确认重新睁开后提交事件 |
| 长闭眼界线 | 1500 ms | 持续低 EAR 达到此时长分类为长闭眼；重新睁眼等待不计入闭眼时长 |
| 最大观测缺口 | 120 ms | 超限或失脸取消未完成眼部事件 |
| PERCLOS 提示线 | 0.25 | 当前闭合样本比例候选口径；不将其称为经临床标定的疲劳程度 |
| 低眨眼率提示线 | 10 次/min（且大于 0） | 原型提示阈值，场景和个体差异尚待标定 |
| 长闭眼次数提示线 | 至少 1 次 | 当前实现计数的行为见下述注意事项 |
| MAR / 哈欠确认 | MAR 大于 0.60，持续至少 800 ms | 排除部分短暂张嘴；没有证明能完全区分讲话与哈欠 |
| 哈欠次数提示线 | 至少 2 次 | 工程候选 |
| 姿态参考界线 | yaw 30°、pitch 25° | 工程候选；另有持续帧、关键点与可见率检查 |
| 人脸可见率下限 | 0.70 | 低于下限提示调整姿态 |
| 持续弹窗确认 | 10 s | 网页持续状态提示；不改变底层检测阈值 |

【已验证：实现注意事项】当前 C 实现的 `blink_count`、`long_close_count`、`yawn_count` 为进程累计计数；眨眼率和 PERCLOS 使用滑窗。视频测试应比较某段时间的计数增量。旧的累计长闭眼/哈欠事件可能继续参与当前风险提示，不能把提示颜色解释成独立人工确认的实时疲劳状态。

根配置中的 `ear_close_threshold=0.21`、`long_close_ms=500` 属于 PC 旧参考；本次板端演示使用表中的 0.400 与 1500 ms。

## 心率与显示参数

| 参数 | 当前值 | 含义 |
|---|---|---|
| rPPG 路线 | `green` | 额头区域绿通道的无接触脉动趋势候选 |
| 有效样本窗口 | 75 点，标称 30 Hz 下对应 2.5 s | 不保证入镜 2.5 秒必出数；质量、FIR、间隙和频谱检查仍可能拒报 |
| 有效历史复用 | 启动后逐渐扩展到最近最多 10 s | 旧点滚动淘汰，失脸/空 ROI/长中断清窗，不复用旧 BPM 充当新样本 |
| 心率搜索频带 | 0.7～3.5 Hz | 对应 42～210 次/min 的算法搜索范围，不是健康/诊断范围 |
| FIR | 63 抽头，Q15 定点系数，30 Hz 设计 | 当前心率 FIR 在 PS 执行 |
| 采样率容差 | ±10% | 真实时基不符时拒报 |
| 最大采样间隙 / 短暂停恢复 | 200 / 200 ms | 更长缺口重新积样；短暂停恢复仍需 3 个新有效样本 |
| 算法 p95 间隔比 | 3.0 | 有限重采样门控；实时性验收门限 1.5 保持 |
| 心率质量门限 | overall 大于或等于 0.75 | 同时还有姿态、光照、运动及 ROI 检查 |
| 短窗额外谱质量门限 | 窗长不超过 3 s 时，谱指标大于 0.80 | 工程门控指标，不是“80%准确率”或概率 |
| 输出稳定器 | 最近 3 次估计；EMA alpha=0.20 | 权重还受谱指标影响；提高视觉稳定性并增加响应延迟 |
| 稳定器纳入间隔 | 0.8 s | 不是相机帧间隔 |
| 稳定器最大有效间隙 | 1.5 s | 超时清空滤波状态 |
| 数字平滑过渡 | 1000 ms | 显示动画保留真实目标说明，不写回原始测量和告警 |
| 缺测历史虚线 | 前后连接上限 30 s；末端延续上限 10 s | 仅供绘图，明确标为历史参考；不是连续有效心率 |
| 原型高心率提示线 | 100 次/min | 未标定的辅助提示阈值 |

【已验证：参数推导】75 点在 30 Hz 下的名义频谱网格间距为 24 次/min；真实有效历史增加后网格可变细。插值、EMA 和网页动画本身不能增加测量信息。【不确定】没有同步参考设备，本轮不计算心率误差或准确率。

### 历史复用版与 60 fps 短测

【已验证】后续历史复用版 20:30:56～20:32:26 的 90 秒记录：448 个不同指标帧、0 次请求错误、378 帧有人脸、18 帧心率非空。此轮当前心率仍间歇，不能据此宣称连续性已经解决。两轮动作和有效人脸覆盖不同，不能直接计算算法提升率。日志确认实际使用的历史点数达到 114，超过 75 点启动下限；相关策略见 [历史复用说明](hr_history_reuse.md)。

【已验证】相机只采集短测采用 640×480 MJPEG、请求 60 fps，300 帧实测 59.185653 fps，驱动序号缺口 0。这是相机采集能力，不是完整检测链达到 60 fps。另一个约 34.8 秒完整运行片段的分析速率为 27.2679 Hz，部分 ERT 帧总耗时约 43～55 ms；60 fps 单帧预算为 16.67 ms。短测后恢复 640×480 YUYV、标称 30 Hz 的正式检测服务，未将整链配置虚改为 60。

当前版本证据：[历史复用与 60 fps 核验](../metrics/evidence/2026-11-03_hr_history_reuse.json)、[新版数值 CSV](../metrics/logs/hr_history_20261103_203056/metrics.csv)。

## 可直接用于视频的介绍词

> 这是知倦 VigiLens，一个基于 Zynq-7020 开发板的无接触疲劳风险提示实验室原型。USB 相机输入图像，FPGA 完成 ROI、灰度和运动量处理，ARM 端计算眼部行为、质量和心率趋势，再通过开发板网页实时展示。目前演示使用 640×480 图像，眨眼采用 EAR 阈值和时间确认，长闭眼界线是 1.5 秒。心率使用 75 个有效样本的短窗，并区分当前有效值、历史参考和缺测状态。

建议视频镜头：硬件与连接 → 当前参数 → 正常睁眼/眨眼/长闭眼计数 → 稳定正视下的心率及拒报原因 → 数据 CSV 与实测结论。不要将动画帧率说成分析帧率，也不要把历史曲线、一次出数或动作提示说成准确性验证。

参数来源：[config.yaml](../config.yaml)、[架构说明](architecture.md)、[眼部候选说明](ear_sensitivity.md)、`board/autonomy/behavior.c` 与本轮板卡参数实读。契约沿革见 [interface.md](interface.md) 第 6 节。
