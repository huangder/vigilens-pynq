## 0. 一句话现状

**板子本身没问题，PL 也能把 25 MHz 送到 `CAM_CLK`；相机 7bit `0x10` 却始终不应答。
现在最硬的解释是：J11 的 `pin 11`（`CAM_GPIO` / 树莓派与 Arducam 都定义为 `CAM_IO0` = **上电使能，高有效**）
在本板上经 `R33 0R(NC)` **未贴**，所以模组的使能脚**悬空、没人拉高** ⇒ 传感器不上电 ⇒ 不应答。**

**唯一"没人管"的控制脚 = pin 11 使能** ⇒ 这就是当前主假设。

## 2. 能确定 / 不能确定

### 能确定【已验证】

1. 板上**没有**驱动相机 `CAM_CLK` 的时钟源：`U19`(50M_OSC)→`R156`(33R)→`PL_CLK_50M`→球 `H16`（FPGA 自己的时钟）；
   `CAM_CLK` = 球 `U9` 是另一张网，只连 J11 pin 12。⇒ **MCLK 只能由 PL 给**（MicroPhase 手册同样写明 MIPI 接在 PL IO 上）。
2. PL 可以把它驱动起来（第 2 轮 25 MHz 档已跑通整条构建/编程/读回链路）。
3. SCCB 主机正常：`U18`(0x50) 与 `0x58` 都在应答，扫描走完（`step=7 DONE`）。
4. 相机 `0x10`/`0x20` **在所有地址都不应答**（两轮独立位流）。
5. **`R33` 未贴**（用户现场目视确认）⇒ `H17` 与 pin 11 之间**没有电气通路**。
6. 25 MHz 落在 IMX219 手册 `INCK` 规格 **6~27 MHz** 之内（`Table 44`：min 6 / typ 18 / max 27 MHz）。

### 不能确定【待物理测量】

1. `pin 15` 的 **3.3 V** 是否真的到模组（从未量过）。
2. `pin 11` 现在的电位（R33 空着时是悬空，模组内部可能有上拉/下拉，需实测）。
3. `0x58` 到底在模组上还是板上（**拔 FFC 重跑 dump** 就能判，10 分钟）。
4. 模组本体是否完好；排线是否插到底（top-contact：金手指朝上）。

## 3. 代码侧：本轮改了什么（`C:`，未提交）

| 文件:行 | 改动 | 为什么 |
|---|---|---|
| `board/cam_detect/pl_cam_detect.v:93-101` | `wire mclk_meas = DRIVE_MCLK ? mclk_r : mclk;` → **`= mclk;`** | 旧写法在"自己驱动"模式下量的是自己的分频器（自证式测量），**证明不了波形出 pad** |
| `board/cam_detect/pl_cam_detect.v:102` | `MEAS_N[15:0]-16'd1` → **`(MEAS_N - 1)`** | 参数位选改算术，与 dump 探针统一 |
| `board/cam_detect/pl_cam_detect.v:611-631` | **`assign led[3] = 1'b1;`**（原 `~(step == STEP_DONE)`） | `led[3]`=`H17` 经 `R33` = `CAM_GPIO`(pin11) = **POWER-EN**，必须**常高**；旧的"跑完拉低"= 扫完断电 |
| `board/cam_detect/cam_detect_pins.xdc` | 5 处注释更正（pin11/pin12/pin15/GND/"坑 2"） | 与原理图对齐，别让下一个人再被误导 |

**新增**（第 3 轮）：`board/cam_detect/pl_eeprom_dump.v`、`pl_eeprom_dump_dbg.v`、`build_dump.tcl`、`read_dump.tcl`、`board/check_eeprom.py`。

> ⚠️ **只改代码不能解决问题**：`R33` 未贴就没有电气通路，`led[3]` 给什么电平都到不了 pin 11。
> 代码改动的作用是**等 R33 补上之后**极性才是对的。
