## 0. 一句话结论

**PL 侧的 SCCB 主机工作正常 —— 它能扫描并认到板载 EEPROM；但 IMX219 在整条实验中
从未应答，chip ID 没读到。相机存活实验尚未通过。**

因此：
- 【已验证】PL 的 I2C 位翻转时序、上下拉、引脚约束是对的（有 EEPROM 作对照）。
- 【已验证】相机那条支路**没有**给出任何应答信号。
- 【未确定】原因在相机、在排线、在时钟，还是在供电 —— 见 §7、§9。

## 1. 目标与判据

**背景**：2026-10-11 早前决定 **舍弃 OpenMV 路线，直接上 IMX219 / Camera Module 2**
（15-pin FFC 排线），并按用户的要求走 **「照 S1 的样子先做一个最小相机存活实验」**
—— 不做完整 Block Design，先用一小块纯 PL 逻辑回答「相机到底活没活」。

**判据（唯一）**：能读到 IMX219 的 chip ID：

| 寄存器 | 期望值 | 出处 |
|---|---|---|
| `reg 0x0000`（MODEL_ID_H） | `0x02` | IMX219 datasheet 常值 |
| `reg 0x0001`（MODEL_ID_L） | `0x19` | 同上 |

**不进 Block Design、不启 PS、不用 DDR** —— 与 S1 的 `board/openmv/pl_uart_echo.v` 完全同一套纪律。

**为什么要扫全总线**：IMX219 的 7-bit SCCB 地址 `0x10` 与「16-bit 寄存器地址」这两条口径，
按 `board/imx219_driver.py` 的登记**都还是 UNVERIFIED**。所以探针**扫 0x00~0x7F**，
并且**两种寄存器地址宽度各读一遍**，把「到底哪一种」变成一次实测而不是一个假设。

## 2. 硬件与引脚

### 2.1 连接器

相机接在板子**侧边的 FFC 座**（原理图第 14 页 `CON15_FPC`，15 pin）。
网络名与 pin 号的对应读自该页；**网络名与 FPGA 球号的对应**是另一回事，见 §2.2。

| pin | 网络名 | 用途 |
|---|---|---|
| 1 / 4 / 7 / 10 | GND | 地（Raspberry Pi 15-pin 惯例） |
| 2 / 3 | `MIPI_CSI_L1_N` / `_P` | MIPI 数据 lane 1 |
| 5 / 6 | `MIPI_CSI_L0_N` / `_P` | MIPI 数据 lane 0 |
| 8 / 9 | `MIPI_CSI_CLK_N` / `_P` | MIPI 时钟 lane |
| 11 | `CAM_GPIO` | 相机侧 GPIO |
| 12 | `CAM_CLK` | 相机 INCK（**见 §2.3**） |
| 13 | `CAM_SCL` | SCCB 时钟 |
| 14 | `CAM_SDA` | SCCB 数据 |
| 15 | **未定** | 【推测】可能是 `VCC_3V3` —— 与 Raspberry Pi 的惯例（pin 15 = GND）**不一致**，是本实验最高优先级的万用表实测项 |

> ⚠️ pin 15 没定清楚之前，**不要把相机直接插上去赌**。2026-10-11 已经因为插反
> 出过一次掉电事故（§8）。

### 2.2 三个相机脚怎么定的【已验证】

**这一条是本次实验里最容易被搞错的地方**：子代理 B 先给出的 `CAM_SCL = B19` 是**错的**
（`B19` 实际是 `PL_KEY4`，`D18` 是 `BT_FM_UART_TXD`）。所以我自己独立复核了一遍。

**用的两张权威源**：
- 原理图 `_mipi_research/extract/fpga-docs-master/schematic/Mizar-Z7_R11.pdf`（18 页）
- AMD 官方封装表 `_mipi_research/xc7z020clg400pkg.txt`

**方法**：在符号页里，**网络名文本相对球号文本有恒定的 x 偏移（−0.54）**，
IO 名相对球号有另一恒定偏移（+3.36）。用 BANK35 的 **56/56 个球**做自校验
（全部满足同一偏移），再与仓库里**已经在上板验证过的 8 个已知点**
（`board/openmv/mizar_z7_openmv_uart.xdc`：`clk H16`、`rst_n R19`、`uart_tx H15`、
`led G14/C20/B20/H17`）逐条比对，全部吻合。

**结果**：

| 连接器 | 网络名 | FPGA 球号 | IO 名 | Bank |
|---|---|---|---|---|
| pin 12 | `CAM_CLK` | **`U9`** | `IO_L17P_T2_13` | BANK13 |
| pin 13 | `CAM_SCL` | **`A20`** | `IO_L2N_T0_AD8N_35` | BANK35 |
| pin 14 | `CAM_SDA` | **`E17`** | `IO_L3P_T0_DQS_AD1P_35` | BANK35 |

⚠️ 权威性：`xc7z020clg400pkg.txt`（AMD 官方）**优先于** `_mipi_research/bank35_map.txt`
（后者有引脚名错位，例如它声称 `H16 = IO_L12N_T1_MRCC_35`，官方文件写的是
`H16 = IO_L13P_T2_MRCC_35`）。

### 2.3 时钟路径 —— 一个必须知道的前提【已验证】

原理图上 **`U19`（板上 50 MHz 有源晶振）经 `R156 33R` 直驱连接器 pin 12（`CAM_CLK`）**。

也就是说：**MCLK 是板上固定的 50 MHz，不是 24 MHz，也不是 PL 输出。**

这带出两个后果：

1. **PL 不能再驱动这个脚**，否则两个源对打。所以 RTL 用
   `parameter integer DRIVE_MCLK = 0` 把 `mclk` 置高阻（见 §3）。
2. **50 MHz 超出 IMX219 的 INCK 规格（6~27 MHz）**。读 chip ID 只需要 INCK 在
   合法范围内、不需要精确 24 MHz —— 但「超规的时钟下 SCCB 到底应不应答」
   **正是本次实验要回答的问题之一**，不是可以直接假设的。

## 3. 探针逻辑

`board/imx219_probe/pl_imx219_probe.v`（486 行，Verilog-2001）。

**端口**：`clk, rst_n, mclk, sccb_scl, sccb_sda, uart_tx, led[3:0]`
\+ 8 个调试输出口（`dbg_sq[2:0]`、`dbg_hit_n[3:0]`、`dbg_hit0/1[7:0]`、`dbg_id0/1[7:0]`、`dbg_id80/81[7:0]`）。

**参数**：`CLK_HZ=50_000_000`、`BAUD=115200`、`SCL_HZ=100_000`、`PROBE_ADDR=7'h10`、
`PWRUP_MS=200`、`DRIVE_MCLK=0`。

**做四件事**：

1. 上电等 200 ms（给相机内部 LDO 起振）。
2. **扫全总线 0x00~0x7F**，记录命中的地址。
3. 对 `PROBE_ADDR` 用 **16-bit 地址**方式读 `0x0000/0x0001/0x0002`；
   再用 **8-bit 地址**方式读同一组。
4. 把结果拼成 96 字节 ASCII 报文，按 115200 8N1 打出去；同时把关键量挂到 dbg 口。

**设计取舍（刻意为之）**：
- SCL 定 100 kHz（SCCB 保守档）。每个数据位 = 3 个 phase
  （SET/SCL 低 → HI/SCL 高 → LO/SCL 低），phase = `CLK_HZ/(3*SCL_HZ)` = 166 clk @50 MHz。
  **这样做的原因：SDA 只允许在 SCL 为低时变化**，否则会被从机当成 START/STOP。
- **只读不写**：不配置相机、不修改任何寄存器 ⇒ 不可能把相机配坏。

## 4. 离线仿真【已验证】

`board/imx219_probe/tb_pl_imx219_probe.v` 内建一个 IMX219 从机模型
（`SLV_ADDR=7'h10`，`slv_regs[0]=0x02, [1]=0x19, [2]=0x00`）+ UART 解码 + 报文断言。

**真实输出**（`_cam_build/sim9.log` 末段，原样誊录）：

```
SCAN 1  20
ID16 02 19 00
ID8  02 19 00
==== RESULT: PASS ====
SCAN hit 0x10; both 16bit and 8bit register addressing read chip ID 02 19
```

⚠️ **这条 PASS 的边界要说清楚**：它证明的是 **RTL 的时序逻辑自洽**（起止条件、
ACK 采样、双地址宽度、报文拼装都对得上）。**它用的从机模型是本工程自己写的，
不等于真相机会应答。** 真相机的结果以 §6 的 ILA 读数为准。

**仿真过程中真实修掉的问题**（留档，避免重复踩）：
1. TB 从机 ACK 极性写反。
2. 寄存器→寄存器之间没有重发 START，导致死锁。
3. **RTL 的 `scl_lo` 漏了 `I_IDLE`** ⇒ 每次 START 后 SCL 与 SDA 同时释放，
   从机看到**假 STOP**，清掉 `in_frame`，永远不数够 8 bit、永远不 ACK。
4. `op_rx` 采样点太晚（中间 STOP 的 `I_IDLE` 负载把 `irx` 清了），`regv16/regv8` 恒为 `00`。
5. TB 从机把读地址字节当成「第二个地址字节」，数据相从不驱动 SDA，主机读回 `0xFF`。

## 6. 上板运行与结果读回【已验证】

### 6.1 为什么最后走 JTAG

探针的 `uart_tx` 在 **JP2 pin 7 = `H15`**，是**裸 GPIO**。而板载 USB-UART
（CP210x，`VID_10C4&PID_EA60` → **COM11**）接的是 **PS 侧的 MIO**，
主机在 `COM11` 上**读不到 PL 的这根线**。

枚举串口只有 COM11 一个 ⇒ 现场没有 USB-TTL 转接板 ⇒ 改走 **JTAG + ILA**。

> 顺带记一条文档修正：板载 USB-UART 是 **CP210x**，不是多处文档写的 CH340
> （`docs/12_硬件清单与接线文档.md:122`、`docs/12:214`、`board/openmv/README.md:671`、
> `docs/30:292`、根 `README.md:158` 都写的是 CH340）。

### 6.2 ILA 链路

`pl_imx219_probe_dbg.v`（探针 + `ila_0`）→ `build_dbg.tcl`（工程式构建 + `write_debug_probes`）
→ `read_ila.tcl`（烧 ILA 版 → `run_hw_ila -trigger_now` → `wait_on_hw_ila`
→ `upload_hw_ila_data` → `write_hw_ila_data -force -csv_file ila_capture.csv`）。

**探针在 `SQ_HOLD` 之后这些值就冻结了，所以直接 `-trigger_now` 抓当前值即可，不需要配触发条件。**
ILA probe 用了 **4 个**（`dbg_sq` 与 `dbg_hit_n` 拼成一个 7-bit probe）——
受 **Vivado BASIC 授权「最多 5 个 probe」** 的限制（`ERROR: [Chipscope 16-620]`）。

### 6.3 原始读数

`board/imx219_probe/ila_capture.csv`（1024 个采样，**未经任何编辑**）：

```
Sample in Buffer,Sample in Window,TRIGGER,dbg_hit_n[3:0],dbg_sq[2:0],dbg_hit0[7:0],dbg_hit1[7:0],dbg_id0[7:0],dbg_id1[7:0],dbg_id80[7:0],dbg_id81[7:0]
Radix - UNSIGNED,UNSIGNED,UNSIGNED,HEX,HEX,HEX,HEX,HEX,HEX,HEX,HEX
```

**1024 个采样，去重后只有 1 种组合**：

| 信号 | 值 | 含义 |
|---|---|---|
| `dbg_sq` | `6` | `SQ_HOLD` —— 定序器**测完了**，不是卡住 |
| `dbg_hit_n` | `2` | 总线上有 **2 个**设备应答 |
| `dbg_hit0` | `0xA0` | 第 1 个 = 7-bit `0x50` = **板载 24C32 EEPROM** |
| `dbg_hit1` | `0xB0` | 第 2 个 = 7-bit `0x58` = 另一个 `0x5x` 段的 EEPROM 类器件 |
| `dbg_id0` / `dbg_id1` | `0xFF` / `0xFF` | 16-bit 地址方式读 `0x0000/0x0001` → 全 1（总线释放，无人给数据） |

**没有 `0x10` / `0x20`（IMX219 的两个候选地址）出现在命中列表里。**

## 7. 判定：能确定什么，不能确定什么

### 能确定【已验证】

1. **PL 的 SCCB 主机是好的** —— 它成功扫描、成功读到 EEPROM 的 ACK，
   说明位翻转时序、开漏三态、板上 4.7K 上拉、引脚约束（`A20`/`E17`）**都对**。
   这是本实验最有价值的一条：主机侧不用再怀疑。
2. **IMX219 对两种地址宽度都没有应答**，`MODEL_ID` 两次都读到 `0xFF`。
3. **定序器跑完了**（`dbg_sq = SQ_HOLD`），所以「读不到」不是逻辑卡死。
4. 设计本身**综合/实现/时序全过**，PL 配置后时钟在跑（JTAG 能稳定读回 ILA）。

### 不能确定【未确定】

⚠️ **`0xA0` 是焊在板上的 EEPROM，位于连接器之前。**
所以它只证明 **PL 主机 + 板上这一段总线**是好的，**完全不证明 FFC 排线到相机那一段是通的**。
把 EEPROM 的应答当成「相机侧链路通」是**错的推断**，这里明确排除。

### 候选原因（未排序为结论，仅列出待查项）

| # | 候选 | 怎么验 |
|---|---|---|
| ① | **相机没拿到合法 MCLK**（§2.3：50 MHz 超规；且原理图有连接 ≠ 板上贴了器件 —— 这块板已有 `R33 0R(NC)` 未贴装的先例） | 万用表量 FFC **pin 12 对 GND 的直流电压**：有 50 MHz 方波时约 **1.6 V**；若 **0 V** ⇒ 没时钟 ⇒ `R156` 未贴或 `U19` 无输出 |
| ② | **排线没接触好 / 供电 pin 没到位** | 量 **pin 15 对 GND**；量排线两端 `pin1↔pin15` 是否短路 |
| ③ | **相机在 §8 那次插反事故里已经损坏** | 换一颗同型号模块对比 |

## 8. 事故记录：排线插反【已验证】

**现象**：相机接上去之后「什么都不亮了」（连之前的 LED 心跳也没了）。

**根因**：**排线插反了**。Mizar 的 FFC 座是 **top-contact** —— 金手指必须**朝上、远离 PCB**。
180° 反插时，`pin1 (GND)` 顶到 `pin15`（【推测】为 `VCC_3V3`），**短路使板子掉电**；
而且这次掉电**把已经烧进去的易失 bitstream 也清掉了**，所以看起来是「全黑」。

**恢复**：重插（金手指朝上）后重新烧录，`PROGRAM: OK`。JTAG 能重新认到器件即证明供电已恢复。

**教训**：
- FFC 插之前**先用万用表确认方向与 pin15 电位**，不要靠手感。
- 这块板的「全黑」是一个**复合故障**（掉电 + bitstream 被清），排查时要把两件事分开。

```powershell
# ③ 带 ILA 构建 + JTAG 读回（需要板卡上电 + JTAG 连着）
cmd /c "call D:\Xilinx\2026.1\Vivado\settings64.bat && vivado -mode batch -source build_dbg.tcl"
cmd /c "call D:\Xilinx\2026.1\Vivado\settings64.bat && vivado -mode batch -source read_ila.tcl"
#    产出 ila_capture.csv —— 与 board/imx219_probe/ila_capture.csv 对照
```

⚠️ **归档的 `.tcl` 里是原样的绝对路径 `D:/Desktop/AMD/_cam_build/...`**
（为保持「这一版就是产生那次结果的那一版」而未改）。换机器/换目录要先改 `set OUT` / `set PROJECT_DIR`。
RTL / TB / XDC 本身不含路径，可直接复用。

⚠️ Vivado 在**受限沙箱**里跑会失败：它要写 `C:\Users\<用户>\AppData\Roaming\Xilinx\...`，
被拒后 IP 目录为空，`create_ip` 建不出 ILA（`WARNING: [Ipptcl 7-1638] No Catalog IPs found`）。
**用完整权限终端跑。**
