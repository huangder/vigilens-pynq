## 3. B 线已经做好的（已实测，不是"应该能跑"）

`POST /api/ingest` **接受一个可选的旁路字段** `triggers`，与 `frame` **平级**（不塞进 frame）：

```json
{
  "frame":    { "...契约帧：9 个字段一个不多一个不少..." },
  "triggers": [
    {"rule": "perclos",    "metric": "behavior.perclos",          "value": 0.321, "threshold": 0.25, "verdict": "fail"},
    {"rule": "long_close", "metric": "behavior.long_close_count", "value": 3,     "threshold": 1,    "verdict": "fail"}
  ]
}
```

- 不带 `triggers` → 行为与从前**完全一致**（向后兼容，已验证）
- `triggers` 不是数组 → 422 + 明确错误原文（不静默吞掉）
- 收到后存成 `{"frame_id": <该帧的 frame_id>, "items": [...]}`，由 `/api/status` 的 `triggers` 字段回给页面
- 前端在 WebSocket 模式下按 1 Hz 取 `/api/status`，**并做两道防呆**：
  1. `frame_id` 必须与正在显示的帧**一致** —— 否则会把"上一帧的理由"贴在"这一帧的状态"旁边
  2. 断流帧（`disconnected`）**不显示**证据链 —— 它的 `frame_id` 是沿用上一帧的，单比 id 会误判

**实测证据**（本机真实运行）：

```text
1) 带 triggers 推送        -> 200 {"ok":true,"published":1}
2) 帧本身仍然合法          -> validate_frame(frame) = []     ← 没有夹带字段
3) /api/status.triggers    -> {"frame_id":12,"items":[...]}
4) 帧里没有夹带 triggers   -> True
5) triggers 传了非数组     -> 422 {"errors":["triggers 必须是数组..."]}
6) 不带 triggers 照常推送  -> 200
浏览器：有数据时显示「[fail] perclos · behavior.perclos = 0.321（阈值 0.25）」；
        断流后自动清空（不显示过期理由）
```

## 4. 请你做的事：在推送处把 triggers 一起带上

**位置：`backend/publish.py` 的 `FramePoster.post()`**，现在第 154 行附近：

```python
payload = {"frame": clean}     # api.py 的 /api/ingest 兼容 {"frame": ...} 与裸帧
```

改成：

```python
payload = {"frame": clean, "triggers": list(frame.get("_triggers") or [])}
```

三个要点：

1. 从**原始的 `frame`** 取 `_triggers`（`clean` 里已经被剥掉了，读它必然为空）
2. **帧本身没变、`validate_frame` 仍然只校验 `frame`**，所以不影响你现有的 17 项 M2 端到端检查，
   也不影响 `test_publish.py` 里"推出去的不许带 `_triggers`"那条断言（那条断言针对 `frame`，
   而 `triggers` 在它外面）
3. 每项的键建议保持你现在的形状：`rule` / `metric` / `value` / `threshold` / `verdict`。
   前端就用这五个渲染，`verdict` 兼作样式（`fail` / `warn` / `pass`）

**如果你觉得该换形状或换字段名，直接说** —— 这是接口，你定了 B 线改前端，不要为了迁就我而将就。

## 5. 为什么不直接把它加进契约

| 方案 | 代价 |
|---|---|
| 加进契约（第 10 个顶层字段） | 改 schema + 两个校验器 + 跨语言检查 + 三方会签；帧变大；而它**不是测量数据** |
| **旁路（本方案）** | 契约不动、校验器不动、帧不动；只动推送的一行 + B 线自己的内部实现 |

理由：证据链是**"给界面看的解释"**，不是测量结果。测量帧应当保持最小且冻结；
解释信息走旁路，将来要改形状也不必动契约。

## 7. 边界与已知限制（不粉饰）

- **只有页面由 `api.py` 托管时证据链才显示**：前端轮询的是同源 `/api/status`。
  走 `websocket.py --mode file`（8765 端口）那条路没有 HTTP 接口，取不到证据链，会安静显示"暂无"。
  这可以接受 —— M2 的正式形态就是 `api.py`。
- **同一时刻只允许一个推送源**（你 P5 复验定的规矩）：两个 `--post` 同时推会让 `frame_id` 交错，
  证据链也会跟着错位。
- **你不做这个改动也没有任何副作用**：网页保持现在这样（那根列表显示"暂无判定证据链"并指向本文档）。
  B 线不会因此阻塞。
