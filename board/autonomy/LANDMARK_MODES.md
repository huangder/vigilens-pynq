# 468 / 478 模式本机视频差异核对

【已验证】2026-10-30，脚本直接使用现有 `MediaPipeLandmarker` 的
`refine_landmarks=False/True`，同一连续视频帧分别推进两套独立跟踪、行为、质量和决策状态。
这份记录比较模型输出，**没有人工真值，不能判断哪侧更准确，也不是 ARM 性能验收**。

复现命令（仓库根 PowerShell）：

```powershell
. .\env.ps1
python board/autonomy/compare_landmark_modes.py --source data/raw/blink.mp4 --output metrics/logs/landmark_modes_blink_300 --frames 300 --rotate 0
python -m unittest discover -s board/autonomy/tests -p test_compare_landmark_modes.py -v
```

输入 `blink.mp4` SHA256：
`5921c741864f3a1daeee0eb619e285363c544783e92970fe4e64e3d3eabcfab1`。
FFMPEG 读取元数据为 640×480、30 fps、656 帧，旋转元数据 0°、自动旋转关闭；
解码形状为 `[480,640]`，显式旋转 0°。实际比较索引 0–299，共 300 帧，视频时间为约 10 秒。
没有上传或导出人脸图像；几何明细与完整数值摘要仅保存于忽略目录
`metrics/logs/landmark_modes_blink_300/geometry.jsonl`、`summary.json`。

本轮环境为 Windows / Python 3.12.13、MediaPipe 0.10.21、OpenCV 4.11.0、NumPy 1.26.4。
配置 SHA256 为 `8a480f594461276776630ae22a6acaa76ae406229c56be486300e0dd28eead39`。

两模式分别重新运行相同后端 PnP 求解器，276 / 274 个检脸帧均通过现有求解护栏；
平均重投影误差 / 双眼外角间距的 p95 分别为 0.09020 / 0.12025。
这个检查在 `detect` 计时之外执行，不新增推理或人工姿态真值。
**通过重投影护栏仍出现大 yaw 分歧，提示 PnP 分支敏感性；不能由此认定任一侧姿态正确。**
后端解算失败返回零角度的既有语义也必须保留为风险，零角度本身不能证明正面朝向。

最终带审计复跑的 PC `detect` p50 分别为 3.4845 / 4.3899 ms，p95 为 4.7952 / 6.0628 ms。
计时含颜色转换、MediaPipe 跟踪和原 PnP，含首帧预热，两模式先后顺序交替；
这些数字只描述该次 PC 运行，不表示板上耗时、30 fps 可行性或完整采集负载。

【推测 / 待验证】两模式的索引可以访问，不代表几何坐标、EAR/MAR、PnP 或额头 ROI 可以沿用同一标定结论。
本次不修改任何阈值、不选择准确率更高的一侧、不估计 BPM；
